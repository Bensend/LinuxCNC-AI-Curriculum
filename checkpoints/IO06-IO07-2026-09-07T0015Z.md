## Key correction to preserve

Do not overstate "DDR last." In standard `hm2_write()`, GPIO Data is prepared and submitted in the aggregate TRAM write **before** `hm2_ioport_write()` performs changed open-drain/inversion/DDR configuration writes. DDR is last only among the IOPort configuration writes. This ordering is source-confirmed but not a blanket electrical glitch-free guarantee.

Also preserve: open-drain `out=1` is release/high impedance; normal push-pull `in/in_not` is documented undefined even though the generic source publishes the IOPort Data sample; failed/temporary reads can leave stale HAL values visible.

## Experiment decision

Stock pinned `hm2_test` is structurally insufficient for runtime GPIO verification because its reads are static and its writes discard address/data. A mutable valid IOPort fake with write capture is promoted to 2000/HIGH. Do not relabel static source inspection as TEST-CONFIRMED GPIO behavior.
