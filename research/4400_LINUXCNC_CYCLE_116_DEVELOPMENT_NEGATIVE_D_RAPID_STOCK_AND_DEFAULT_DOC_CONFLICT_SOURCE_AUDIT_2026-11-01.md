Stable peck gap is fixed by [`G83_RAPID_DELTA`](https://github.com/LinuxCNC/linuxcnc/blob/86cdca76fa2a36274c432caa21952b23c267989a/src/emc/rs274ngc/interp_internal.hh#L55).
2. Development [`Interp::read_d`](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/src/emc/rs274ngc/interp_read.cc#L352) uses `read_real_value`, stores `d_number_float`, and checks duplicates but **does not require a positive D**. Its preceding comment still describes older tool-index validation and is not the executed rule.
3. Development [`check_other_codes`](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/src/emc/rs274ngc/interp_check.cc#L260) explicitly permits D on G73/G83. The inspected G73/G83 [XY dispatch](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/src/emc/rs274ngc/interp_cycles.cc#L992) checks whether Q was supplied and the helper [`convert_cycle_g73`](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/src/emc/rs274ngc/interp_cycles.cc#L202) / [`convert_cycle_g83`](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/src/emc/rs274ngc/interp_cycles.cc#L140) checks **Q>0**, but neither helper validates **D>0** before using it as a rapid offset.
4. The rapid destination is `current_depth + D`, emitted via [`cycle_traverse`](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/src/emc/rs274ngc/interp_cycles.cc#L2240) as `STRAIGHT_TRAVERSE`. For negative D this destination is **deeper** than the just-fed bottom. That is a source-derived command path, not physical cutting evidence.

## Numerical counterexample (source-derived; NOT RUN)
G17/G21/G90/G99, initial Z=5 mm, R=2 mm, bottom Z=-1 mm, Q=1 mm, **D=-0.5 mm**. After the first feed peck to Z=1 mm:
- **G73:** next commanded rapid is to Z=1 + (-0.5) = **0.5 mm**, i.e. 0.5 mm *deeper* than the previous feed cut. The following feed targets Z=0 mm.
- **G83:** commands a rapid to R=2 mm and then another rapid to **0.5 mm**, again crossing the last feed depth (1 mm) by 0.5 mm at rapid rate. The following feed targets Z=0 mm.
- This conditional command sequence could drive a tool rapidly into material not previously removed. Whether the actual machine executes it, stops, faults or collides is **UNKNOWN**. A positive D greater than Q instead creates the above-R excursion in CYCLE-115.

## Conflicting public defaults
Development [G73 page](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/docs/src/gcode/g-code.adoc#L2304) and [G83 page](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/docs/src/gcode/g-code.adoc#L2927) still describe a default 0.010 inch / 0.254 mm. Development [`Interp::init`](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/src/emc/rs274ngc/rs274ngc_pre.cc#L848) and [INI fallback](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/src/emc/rs274ngc/rs274ngc_pre.cc#L946) actually select **0.050 inch / 1 mm**; the [INI reference](https://github.com/LinuxCNC/linuxcnc/blob/06864e23559e70463fc7112d5ce77138bcbc288c/docs/src/config/ini-config.adoc#L642) documents these larger defaults. This is a same-revision **DOC/SOURCE-CONFLICT** between G-code prose and implementation, partly resolved by the INI reference; it is not evidence of an installed machine's parameter values.

## Implementation guidance and evidence classification
For a CAM post targeting development G73/G83, validate finite positive Q and finite positive D when D is used, and apply the stronger conservative post rule `0 < D <= Q` if intermediate rapid targets must remain at or below R. When D is omitted, obtain the actual `[RS274NGC] G73_PECK_CLEARANCE/G83_PECK_CLEARANCE` or the verified binary default; reject unknown configurations instead of assuming the G-code prose's 0.254 mm. For stable v2.9.10 **do not emit D** for these cycles. A D range gate in a CAM post is ordinary process validation, not an independent protective function.
