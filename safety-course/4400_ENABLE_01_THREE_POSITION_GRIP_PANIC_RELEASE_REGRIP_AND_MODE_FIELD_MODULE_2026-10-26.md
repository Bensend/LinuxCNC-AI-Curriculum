# ENABLE-01 — Three-position enabling grip: setup mode, panic squeeze and no-surprise restart
**4400 safety | 2026-10-26 | PUBLIC PAPER TRAINING | NON-GRADUATED | UNSCORED**

Read [the original EUCHNER/IDEC source audit](../research/4400_ENABLE_01_EUCHNER_IDEC_THREE_POSITION_TEACH_ENABLE_RELEASE_REGRIP_SOURCE_AUDIT_2026-10-26.md) first. This module is not a press-brake safety circuit, a live test procedure or an external evaluation. No selected OpenPressBrake enabling device is established.

## Learner objective
Given a proposed setup/jog architecture, distinguish **three-position switch mechanics**, **safe-channel evaluation**, **mode authority**, **ordinary motion command**, **physical final-element withdrawal**, **actual gravity-load holding**, **fault reset** and **deliberate restart**. Describe what evidence would falsify a claimed safe setup mode. Do not assume that slower LinuxCNC motion is safely limited motion.

## Conceptual state chain (NOT wiring)
1. **MODE:** qualified selected/secured setup mode; what guards become unavailable and what alternative protection is required?
2. **ENABLE:** safety evaluator sees exact approved two-channel three-position pattern (1 OFF, 2 ON, 3 OFF; 3→1 stays OFF).
3. **COMMAND:** separate intentional jog request, never generated by enabling-grip transition alone.
4. **PHYSICAL:** independent safety outputs/final elements control the relevant energy path; stopping and load retention have independent machine-specific witnesses.
5. **REARM:** complete release after squeeze/fault; receiver channel recovery is not automatically a machine restart. Recheck selected mode, guard status, hazard zone and fresh jog request.
6. **MAINTENANCE:** enabling grip and setup mode do not replace energy isolation/LOTO, trapped-pressure control or mechanical support.

## Ten unscored adversarial PAPER cases
For each, the learner must state **observable evidence, independent safety decision, physical hazard, needed proof and unresolved facts**. No answer key or numeric acceptance criteria are supplied.

| ID | Scenario / false shortcut to challenge | Required discriminator |
|---|---|---|
| EN-01 | Operator squeezes from middle to full while the LinuxCNC jog button remains down. | Does enabling withdraw independent authority, and what physically stops/holds the axis? |
| EN-02 | Operator releases from full squeeze through middle while the jog key is still held. | Prove **no transient enable** on 3→1 and no stale-command motion on regrip. |
| EN-03 | A replacement switch has the same housing but is EUCHNER **ZSA1 two-stage**, not ZSA2 three-stage. | Exact part suffix/manual and why 2-stage is not equivalent for a safety circuit. |
| EN-04 | Two contact channels are wired to a safety input configured for the opposite equivalent/antivalent pattern. | Exact contact topology, receiver configuration and discrepancy/fault behavior. |
| EN-05 | Thumb fatigue briefly releases one channel; HMI fault clears while the grip never reaches position 1. | Distinguish fault acknowledgment, full-release witness and machine fresh-start. |
| EN-06 | Operator wedges the grip in the middle position to make setup easier. | Defeat incentive, redesign, supervision, independent guard/mode boundary. |
| EN-07 | Two people enter a robot/press cell; only one has a grip. | Multi-person risk and manufacturer instructions; never infer that one grip protects both. |
| EN-08 | HMI says 'slow jog', but speed limit is implemented only in ordinary LinuxCNC parameters. | Ordinary speed command versus independently validated safe limited speed, stopping and holding. |
| EN-09 | A portable pendant is disconnected and reconnected with a jog command still active. | Actual station-selection, connector topology, independent E-stop availability and rearm. |
| EN-10 | Machine power returns with grip at position 2, selected setup mode and a remembered motion request. | Safe default on restoration, deliberate rearm, fresh separate start and physical witness. |

**No scoring:** all EN-01..EN-10 **PUBLIC PAPER / UNSCORED**. The questions are instructional; an information-separated evaluator must select different unseen cases and score only after an immutable learner precommitment.
