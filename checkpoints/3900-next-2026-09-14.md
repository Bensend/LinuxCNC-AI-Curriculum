## Core purpose

3900 is an incubator, not a miscellaneous bucket. Its job is to identify genuinely distinct machine-control patterns that do not yet justify a permanent numbered specialization, study enough real LinuxCNC implementations to understand them, and promote a machine family only when evidence supports a full track.

The transferable skill is selecting the right LinuxCNC abstraction for an unusual physical process rather than forcing every mechanism into ordinary mill-style XYZ G-code.

## Abstraction decision framework to preserve

For each unusual mechanism, explicitly decide whether it is best represented as:

- ordinary coordinated axis/coordinate;
- process-slave/electronic gearing;
- extra joint / independent bounded auxiliary motion;
- HAL realtime process loop;
- state machine / ClassicLadder / custom component;
- purpose-built UI/input filter/external application translating domain intent into LinuxCNC commands.

This decision must be justified from the machine physics and operator workflow.

## Promotion rule

A 3900 branch can become its own permanent numbered track only after:

1. multiple real LinuxCNC implementations or sustained community activity exist;
2. it contains control problems not already covered adequately by existing tracks;
3. enough source/config/build evidence exists for implementation-level teaching;
4. the operator/CAM/process workflow is meaningfully distinct;
5. there is enough nonduplicate depth for multiple lessons without filler.
