## Source contract for counter-mode 1
LinuxCNC `v2.9.10` `src/hal/drivers/mesa-hostmot2/encoder.c` blob `9719d41419da9220761637e002024cdc9d17a8ba`, around lines 105–114, maps HAL bit `counter_mode` to `HM2_ENCODER_COUNTER_MODE`; lines 653–654 export the HAL parameter and line 687 defaults it to zero. `src/hal/drivers/mesa-hostmot2/hostmot2.h` blob `004bf458efcc2d18dbacde09e0b90ba2119252e7` defines `HM2_ENCODER_COUNTER_MODE (1<<10)`. The FPGA edge-decoding algorithm is **not** contained in these C files.

LinuxCNC 2.9 HostMot2 manpage explicitly defines false as quadrature, true as Step/Dir (A step, B direction). Encoder position is count / scale, and velocity is in position units per second. A Mesa developer's forum explanation (PCW, 2021-04-05, [HostMot2 encoder details](https://forum.linuxcnc.org/10-advanced-configuration/42147-hostmot2-encoder-details)) specifies counter-mode 1 counts rising A edges, with direction from B at that edge; quadrature mode counts four edges per A/B cycle. This supports a **one-count-per-A-rising-edge** model, not an assumption that 1.0 scale is necessarily wrong.

The SB1001 sets `counter-mode 1` and `ENCODER_SCALE = 1.0`. Thus if physical A emits **exactly one rising edge per spindle revolution**, reported `spindle.0.revs` can represent true revolutions. If A emits N edges per spindle revolution, the required scale is N counts/revolution (assuming 1:1 spindle pickup and appropriate B direction). If A is derived from motor rotation upstream of a selectable gear train, a fixed scale may not represent spindle revolutions across gear changes. The actual A/B/Z sensor topology, gear placement, B state, and index phase remain unverified.

## Additional diagnostic finding: raw feedback, not lowpass
The core HAL calculates `scale.spindle` (RPS→RPM), `abs.spindle`, and `lowpass.spindle`, producing `spindle-vel-fb-rpm-abs-filtered`. But `near.0.in2` is connected to **`spindle-vel-fb-rpm-abs`**, the **pre-lowpass** signal. `lowpass.spindle.gain 1.` also does not establish meaningful filtering. The post-GUI file displays the filtered signal separately. Do not attribute near comparator behavior to the displayed filtered trace. Since `near.0` executes after `motion-controller`, a newly calculated at-speed result is available to motion on its *next* servo pass, subject to prior HAL signal state.
