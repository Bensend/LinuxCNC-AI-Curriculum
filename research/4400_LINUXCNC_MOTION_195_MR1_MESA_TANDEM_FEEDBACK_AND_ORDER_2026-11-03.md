## Distinguishing implementation findings
The HAL loads `hm2_eth` with `num_encoders=1 num_pwmgens=1 num_stepgens=5` and instantiates `pid.x`, `pid.y`, `pid.y2`, `pid.z`, and `pid.s`. Its explicit servo-thread order is HostMot2 read → motion command handler → motion controller → axis/spindle PID → spindle signal conditioning → HostMot2 write. **However**, `or2`, `not`, and `debounce` functions are appended *after* HostMot2 write. Therefore a signal generated by those functions and consumed by the write stage cannot be assumed to affect hardware in that same servo invocation; exact delay depends on signal path and driver behavior.

For all four linear joints, `joint.N.motor-pos-cmd` drives PID command and `hm2_7i96s.0.stepgen.N.position-fb` drives both PID feedback and `joint.N.motor-pos-fb`. The PID output drives `stepgen.N.velocity-cmd`; joint amplifier enable drives stepgen enable. These are *software-loop-closed step generators*, not independently encoder-measured linear joints. In contrast, the single HostMot2 encoder is configured in the spindle section: encoder position and velocity feed spindle-revolution and speed signals. **Encoder count in a HostMot2 load line is not evidence of encoder-backed axes.**

The Y and Y2 joints have distinct PID, stepgen, home-switch and feedback nets. This demonstrates separately commanded joints in a tandem-axis configuration, but does **not** establish independent mechanical squareness or reliable gantry alignment: both feedback paths are stepgen-derived, not externally measured position. Inspect `[KINS]`, `[TRAJ]`, `[JOINT_1]`, `[JOINT_2]`, home sequences and kinematics before asserting homing behavior.

## Reproducible disconnected inspection
Pin the two blob objects above. Compare `addf` ordering with every `net` producer/consumer. Build a four-column worksheet: joint index; motor-pos-fb producer; actuator command consumer; independent sensor present? For joints 0–3 the fourth column is **not established** by the HAL (all feedback is stepgen). Repeat for spindle and distinguish measured encoder speed from measured linear position. Cross-check all `[JOINT_N]` limits and scales against HAL substitutions before adapting the configuration.

**Adversarial predictions (not executed):**
1. Mechanically stall Y2 while its step generator continues emitting pulses: Y2's stepgen-derived position feedback may still track the commanded step count; a following-error monitor alone cannot prove mechanical motion. Requires physical/plant-model test.
2. Freeze the spindle encoder with the spindle commanded: spindle speed feedback should differ from command if the encoder path is active; no claim about actual shutdown without tracing PID and spindle fault handling.
3. Move a debounce input just before `hm2.write`: the debounce function runs after write in this file, so a newly computed debounce output is not available to that write invocation. Determine whether its consumer is a later function or next-cycle write before assigning a latency.
