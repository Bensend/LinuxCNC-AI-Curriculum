# 4400-M60-M30-01 — Documented pallet exchange versus the default no-op canonical implementation
**2026-10-29 | SOURCE/DOC conflict | 4000 safety course | NON-GRADUATED | NO runtime, physical test, or independent evaluator**

## Exact safety question
Does an unmodified LinuxCNC `M60` exchange a pallet before stopping, and does `M30` exchange a pallet before program end? **Not in the inspected stock canonical implementation.** Both interpreter branches call `PALLET_SHUTTLE()`, but that function has an **empty body** with the explicit source comment `FIXME-- unimplemented`. `M60` then issues an ordinary program pause; `M30` follows its program-end path. A machine-specific remap, custom code, external controller, or physical equipment may behave differently: **the selected machine must be inspected; no universal "no pallet moves" claim is justified**.

This is a **new exact implementation/documentation mismatch**, not a new generic pallet-safety competency. Compare the existing [APC-01 Haas original-OEM investigation](4400_APC_01_HAAS_PALLET_CHANGER_EARLY_CLAMP_SENSOR_HYDRAULIC_REVERSE_AND_SERVICE_JUMPER_OEM_AUDIT_2026-10-27.md), [M0/M1 normal pause audit](4400_LINUXCNC_M0_M1_PAUSE_RESUME_VS_SAFE_ACCESS_SOURCE_AUDIT_2026-10-27.md), and [ATC-02 M6 tool-changed handshake audit](4400_LINUXCNC_PINNED_M6_IOCONTROL_TOOL_CHANGED_ACK_VS_PHYSICAL_RETENTION_SOURCE_TRACE_2026-10-25.md). APC-01 concerns real OEM pallet position/retention and option-dependent E-stop; the present delta is **stock LinuxCNC's absent pallet actuation despite an affirmative M-code manual description**.

## Causal sequence and safety boundary
1. **Stock `M60`:** parser/interpreter accepts group-4 M60; it flushes preceding canonical operations; invokes the no-op pallet function; queues `EMC_TASK_PLAN_PAUSE`. The default branch does **not** command pallet movement and does **not** automatically stop spindle or coolant. A normal Resume can continue subsequent program lines. A PAUSED indication proves neither pallet exchange nor human-safe access.
2. **Stock `M30`:** interpreter's program-end branch resets normal modal/spindle/coolant state, invokes the same no-op pallet function, and queues `EMC_TASK_PLAN_END`. This differs from M60's pause semantics. Neither an ENDED display nor the word "exchange" in the manual is a physical pallet-position witness.
3. **Configured `M60` remap:** the custom handler **replaces** the stock group-4 path. Its wait/abort/timeout, reentry, program pause, and external pallet-control behavior are configuration-specific. A remap can be perfectly legitimate, but must be independently inspected; the presence of `REMAP=M60` alone proves no physical completion or safe-access function.
4. **Separate safety authority:** ordinary G-code/HAL/remap/PLC sequence can request a pallet exchange and diagnose sensors. Independent safety-related logic must own access protection, unexpected start prevention and hazardous-energy removal/containment as required by the selected risk assessment. Physical retention/clamp/position/occupancy must be witnessed by justified devices and validated on the real machine. A generic "pallet changed" bit or program pause is not an adequate single witness.

## Practical integration/validation requirements (no machine operation authorized)
- **Design-time gate:** inventory exact LinuxCNC commit, INI `[RS274NGC] REMAP` declarations, handler files, HAL/PLC output and feedback ownership, and any external pallet controller. Read actual code and schematic, not only the M-code manual.
- **Normal control:** require explicit exchange request, bounded timeout, phase-aware position/clamp/lock feedback, stale-sensor rejection, recovery after abort/power loss, and a separate deliberate cycle-start transition. Never silently advance on a generic pause or stale "changed" signal.
- **Safety-related functions:** define danger-zone access, pallet-motion containment, guard/interlock behavior, emergency stop, retained loads, and restart prevention with selected safety devices. Do not allocate personnel safety to an unqualified M60 remap, ordinary LinuxCNC Task or FPGA.
- **Physical proof:** qualified reviewer verifies selected pallet, clamp and access mechanisms and independent protective devices under a separately approved safe procedure. A paper review is **not** a release or permission for personnel-exposed operation.
- **Human factors:** HMI should show `EXCHANGE NOT IMPLEMENTED` where appropriate, or `REQUESTED / MOVING / CLAMP UNKNOWN / PHYSICALLY VERIFIED` with provenance and freshness. Make correct guarding and access procedure simpler than bypassing it.
