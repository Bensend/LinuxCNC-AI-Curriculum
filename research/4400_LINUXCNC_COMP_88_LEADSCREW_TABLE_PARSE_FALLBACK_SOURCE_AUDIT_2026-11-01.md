## Trace: file to realtime motor command

\`[JOINT_n] BACKLASH\` is sent to Motion first; \`COMP_FILE\` then calls \`emcJointLoadComp -> usrmotLoadComp\`. Each line must produce three doubles through \`sscanf("%lf %lf %lf")\`. For type 0, the loader converts measured forward/reverse positions to \`nominal - measured\` trims; for type 1 it passes the supplied trims unchanged. Each valid row is sent separately as \`EMCMOT_SET_JOINT_COMP\`; Motion appends it, derives segment slopes and retains -DBL_MAX/+DBL_MAX sentinels. The realtime \`compute_screw_comp\` chooses forward/reverse interpolation by **joint commanded velocity sign**, retains the prior target at zero velocity, and ramps \`backlash_filt\` toward \`backlash_corr\`. \`motor-pos-cmd = joint-pos-cmd + backlash_filt + motor_offset\`; \`joint-pos-fb = motor-pos-fb - (backlash_filt + motor_offset)\` in the normal feedback path. **The trim is not an immediate coordinate jump**; motor command and feedback both pass through the compensation transformation. Physical tool-point accuracy is not established by HAL feedback alone.

## New discrepancy A — malformed lines stop loading, without a parse error

Both pinned loaders \`break\` on the **first** line where \`sscanf\` does not yield three values; they do not skip comments or blank lines, and they return their accumulated command-transport result (initialized to zero), not a parse-error code. A leading \`# heading\` or blank line can therefore make an existing, readable \`COMP_FILE\` load **zero entries** and return success. A malformed line after valid rows leaves only the valid prefix loaded. A trailing annotation after three valid numbers is different: \`sscanf\` already returns three and the line is accepted. This is **SOURCE-CONFIRMED**, not an observed startup failure.

**Doc/source conflict:** official docs say \`COMP_FILE\` takes precedence over \`BACKLASH\`, but \`compute_screw_comp\` chooses the table only when \`comp.entries > 0\`. If the file is present but zero entries were accepted, the runtime instead applies \`+/- BACKLASH/2\` when velocity is nonzero. If BACKLASH is zero, the correction is zero. The mere presence of the INI key is not the runtime discriminator.

## New discrepancy B — table validation errors are logged but not rejected by the loader

\`EMCMOT_SET_JOINT_COMP\` reports an error for non-increasing nominal positions or more than \`EMCMOT_COMP_SIZE = 256\` entries, then breaks out of the switch **without changing** \`emcmotStatus->commandStatus\`, which was set to \`EMCMOT_COMMAND_OK\` for the new command. \`usrmotWriteEmcmotCommand\` treats an echoed OK as transport success. Thus the file loader can return success while one or more rows were **not** appended. This differs from a missing file, which \`fopen\` explicitly reports as failure. The array uses sentinels, so a truncated accepted prefix can still interpolate/hold an endpoint without necessarily faulting.

## Worked reference, machine units (not a machine calibration)

For type 0 rows \`0 0.002 -0.003\` and \`10 10.004 9.998\`, accepted trims are (forward,reverse) \`(-0.002,+0.003)\` at 0 and \`(-0.004,+0.002)\` at 10. At nominal 5, **target** trims interpolate to \`-0.003\` forward and \`+0.0025\` reverse. The equivalent type 1 rows are \`0 -0.002 0.003\` and \`10 -0.004 0.002\`. Only after the filter settles, and assuming motor_offset=0, the corresponding motor command would be 4.997 or 5.0025. These are arithmetic expectations, **not executed LinuxCNC output**.

## Engineering implication and limits

Before deploying a compensation file, reject zero rows, headers/blank lines, malformed/trailing text, nonfinite values, unordered or duplicate nominal values, >256 rows and wrong units. Do not assume live reload replaces existing rows; [COMP-89](4400_LINUXCNC_COMP_89_TCL_RELOAD_JOINT_AND_ACK_SOURCE_AUDIT_2026-11-01.md) traces that separately. For step generators, the official INI docs require extra \`STEPGEN_MAXACCEL\` headroom (typically 1.5–2 times joint MAX_ACCELERATION), because compensation motion adds to nominal trajectory motion; this is a configuration constraint, not a measured guarantee.
