# 4400-G28-G30-01 — LinuxCNC persistent reference positions, intermediate rapid traverse and safe-retreat misconception
**2026-10-28 | NON-GRADUATED source-level 4400 safety/control boundary | documentary only.** Overall session UTC start 2026-10-28T19:32:03.912Z; second safety branch selected at 2026-10-28T19:38:09.919Z after G38-PROBE-EDGE-01 reached a source-only information-gain stop.

## Concrete safety question and predecessor check
Can an operator, machine builder or G-code author safely equate `G28`, `G30`, `G28.1`, `G30.1` or a successful tool-change-position move with verified physical homing, collision-free retreat, guarded access, or independent hazardous-motion stopping? **No.** This audit addresses a **different causal mechanism** from [G38-PROBE-EDGE-01](4400_PROBE_EDGE_01_LINUXCNC_2910_G38_PRESTATE_EDGE_AND_FALSE_SUCCESS_SOURCE_AUDIT_2026-10-28.md): G28/G30 combine *persistent mutable absolute-machine reference parameters* with *ordinary rapid traversal through an optional intermediate point in the active coordinate system*. Direct canonical index, research plan, historical progress and cumulative design scan found no prior G28/G30 source trace. Existing ATC/tool-capture, POS-TRUST and M19 standstill lessons teach related physical boundaries but not this two-traverse source path.

## Exact normal-control behavior and hypothetical failure paths
| Normal instruction or condition | Source/documented behavior | Safety-relevant discriminator |
|---|---|---|
| `G28.1` or `G30.1` | Stores **current** absolute machine reference parameters | Stored reference is not a qualified safe position or verified home switch |
| `G28` / `G30` without axis words | Rapid toward stored reference for **all axes** (machine-origin fallback if not stored) | No guaranteed Z-first motion, no independent fixture/occupancy protection |
| `G28 Z2.5` (illustrative) | Rapid to Z2.5 in active coordinate system, then to stored machine-reference Z | Intermediate waypoint is not necessarily an unobstructed machine-coordinate Z |
| `G28 X0 Y0` on a trivial XYZ machine | First rapid moves selected X/Y toward work-coordinate zero; second rapid moves selected X/Y toward stored reference | Z need not retract first; fixture/tool collision is a **conditional inference**, not an observed failure |
| `G30` with `TOOL_CHANGE_AT_G30=1` | G30 stored reference can be used for M6 positioning | Does not prove tool release/capture, spindle stop, guards, or deliberate restart |
| Reference altered by a program/offset edit | Subsequent G28/G30 path can change while the command text stays identical | Verify parameter identity, fixture/setup clearance and change approval |
| Machine not physically position-trusted | Source command still expresses requested coordinates, subject to normal controller prerequisites | No inference of physical trust, safe position or personnel-protection authority |
| Guard opens during a rapid | Ordinary G-code path is not independent protective control | Guard/safety system must separately command and prove physical safe state |

**Important limits:** The source and docs prove the two-leg **normal trajectory** and persistent coordinate inputs. They do **not** prove any particular collision, tool-change hazard, guard bypass, speed, distance, stopping time or selected-machine failure. Motion travel-limit checks still exist; a path within axis/joint travel can nevertheless intersect a fixture or hazard zone. This is a reason for risk-derived machine-specific planning, not a claim that G28 bypasses software limits.

## Design and human factors
**Normal control:** use explicit, reviewable and versioned setup/fixture-aware travel paths. Prefer a named machine-specific tool-change/retreat procedure with clearly ordered clearance moves over treating `G28` as a magic safe-home instruction. Review active coordinate system, tool offsets, stored 516x/518x values and axis selection. Make a bad reference easy to diagnose and correct without defeating guards.

**Independent safety:** guard/access control, hazardous-motion stop, actual standstill and holding, mechanical/electrical/hydraulic energy isolation, and deliberate rearm/restart must remain outside ordinary LinuxCNC/HAL/FPGA. A completed `G28`/M6 position is at most an ordinary status input to a broader design; it cannot be sole permission for personnel entry.

**Physical proof:** a qualified selected-machine reviewer must independently establish reachable hazards, fixtures, stop/coast/hold, guard coverage, gravity-load restraint, tool capture, energy isolation, change-control and restart behavior. For a press brake, a G30 backgauge/tool position is not Y1/Y2 ram holding. For a mill or lathe, a rapid to a reference is not spindle standstill. For robots/automated cells, a home pose is not proof that no person remains in the danger zone.

**Maintenance/bypass:** do not make tool changes or service so inconvenient that operators bypass guarding or edit reference parameters without authorization. Provide a clearly labeled verified machine-specific setup path, visible parameter/fixture identity and an approved guarded maintenance route. If the independent minimum safe-to-operate threshold is unproved, **do not operate with people exposed**; experimental operation requires separately approved isolation/remote control, people outside the danger zone and explicit residual-risk assessment.

## M6 tool-change source continuation — direct G30 move is **not** the two-leg G30 command
[Tagged `Interp::convert_tool_change` L5565–5659](https://github.com/LinuxCNC/linuxcnc/blob/86cdca76fa2a36274c432caa21952b23c267989a/src/emc/rs274ngc/interp_convert.cc#L5565-L5659), same blob `f01a359652d588d59c9e210fa441a99d2ee19598`, establishes the actual M6 sequence in the inspected normal interpreter:
1. `START_CHANGE`; unless `tool_change_with_spindle_on` is set, emit `STOP_SPINDLE_TURNING` ordinary command. This is **not** proof of spindle standstill or safe tool access.
2. If `tool_change_quill_up` is set, compute machine-coordinate Z zero and emit a separate Z `STRAIGHT_TRAVERSE`. Without that option, **do not assume a Z-first retract**.
3. If `tool_change_at_g30` is set, read persistent 5181–5189 G30 coordinates, optionally index A/B/C one at a time, then emit **one direct** `STRAIGHT_TRAVERSE` to that reference. This M6 path **does not call `convert_home`** and does **not** use the G30 command's optional intermediate axis-word waypoint. The two-leg claim applies to **G28/G30 commands with axis words**, not automatically to M6.
4. Then emit `CHANGE_TOOL` and update ordinary tool-change state. Physical spindle stop, guard locking, tool capture and safe restart are separate independent safety propositions.

**Practical consequence:** two visually similar routes to a G30 reference can have different intermediate motion. A technician reviewing a machine must distinguish a program's explicit `G30 axes` from M6's `TOOL_CHANGE_AT_G30` option and inspect `TOOL_CHANGE_QUILL_UP` and `TOOL_CHANGE_WITH_SPINDLE_ON` independently. All SOURCE-CONFIRMED at tagged v2.9.10; no machine motion or fault was executed.


## Ordinary homing prerequisite is conditional, not physical position trust
[Tagged `emctaskmain.cc` L147–153, 2204–2215, 2293–2301 and 3245–3261](https://github.com/LinuxCNC/linuxcnc/blob/86cdca76fa2a36274c432caa21952b23c267989a/src/emc/task/emctaskmain.cc#L2198-L2215), blob `7292a172023a5b42b023447c2458cb766c93fc9b`, establishes a **Task-level** ordinary prerequisite: by default `NO_FORCE_HOMING=0`, MDI execution and Auto program run are rejected if any joint's normal `homed` status is false. `[TRAJ] NO_FORCE_HOMING=1` disables that Task precondition. `convert_home` itself is **not** a switch/index homing routine and does not independently validate a physical home.

This distinction matters in both directions: **do not claim** an ordinary unhomed G28 can always execute (Task may block it), and **do not claim** a passing Task homed-status gate or the `NO_FORCE_HOMING` option proves trustworthy physical position, a clear retreat route or independent safety. See the pre-existing [POS-TRUST source audit](4400_POS_TRUST_01_LINUXCNC_2910_VOLATILE_HOME_ESTOP_AND_PHYSICAL_REFERENCE_BOUNDARY_SOURCE_AUDIT_2026-10-28.md) for why HOMED and physical trust differ. No actual machine config was inspected.


## Practical normal-control alternative — explicit G53 is more inspectable, not safety-rated
[Tagged `interp_find.cc` `Interp::find_ends` L125–210](https://github.com/LinuxCNC/linuxcnc/blob/86cdca76fa2a36274c432caa21952b23c267989a/src/emc/rs274ngc/interp_find.cc#L125-L210), blob `4c7255662357f1e570cbad49e80bc8322929a177`, has a G53 branch converting explicitly requested **machine coordinates** into current internal coordinates while accounting for active offsets. [Official G53 docs L1631–1660](https://github.com/LinuxCNC/linuxcnc/blob/86cdca76fa2a36274c432caa21952b23c267989a/docs/src/gcode/g-code.adoc#L1631-L1660) say G53 is **nonmodal**, must appear on each applicable line, and G0/G1 mode must be active. A deliberately ordered, machine-specific sequence of explicit `G53 G0` clearance waypoints can be **easier to inspect** than hidden persistent G28/G30 reference state, provided the selected machine's trusted reference, kinematics, fixture geometry and path are verified. This is a **normal-control human-factors recommendation**, not a guarantee of collision-free movement or a replacement for independent safety.

**Critical distinction:** `G53 G0 X0 Y0 Z0` still commands an ordinary combined rapid to a point; it does not automatically retract Z before XY. Separate ordered commands are required if the machine-specific risk assessment demands that sequence. Do not copy example coordinates to a real machine; no actual clearance point is known here.


## Stored “current position” is interpreter-derived, not an independent physical witness
[Tagged `Interp::convert_savehome` L2461–2532](https://github.com/LinuxCNC/linuxcnc/blob/86cdca76fa2a36274c432caa21952b23c267989a/src/emc/rs274ngc/interp_convert.cc#L2461-L2532) calculates the G28.1/G30.1 persistent reference from `settings->current_x/y/z/...`, axis offsets, active origin offsets, rotation and tool offsets. The function itself reads **no independent physical encoder/limit/guard witness**. **SOURCE-CONFIRMED:** it stores an interpreter-derived absolute coordinate representation, not a separately validated physical safe pose. The interpreter's `current_*` may have been synchronized to normal motion status elsewhere; this audit does **not** assert a universal command-versus-feedback error or that the saved value is necessarily wrong. **INFERENCE:** if normal position reference/offset state is untrusted, storing it cannot repair that trust. This sharpens the existing POS-TRUST-01 boundary without duplicating its E-stop/homing mechanisms.


## 2026-10-29 tagged G53/G91 source-depth correction (not a new safe-retreat method)
