## Question, predecessor and classification

Does a development preflight cover constant-surface-speed (G96) changes along an X move? ## Exact call chain and two discriminators
`read I/K/S/$ → check_other_codes → Interp::convert_straight(G33.1) → [development: check_spindle_sync_feed(K*I)] → START_SPEED_FEED_SYNCH(K) → RIGID_TAP(x,y,z,I) → Task EMC_TRAJ_RIGID_TAP → motion EMCMOT_RIGID_TAP → tpAddRigidTap`. In stable, the bracketed per-axis preflight is absent. Both versions clamp I<1 to 1.

**D1, simple metric Z-only arithmetic (INFERENCE, NOT RUN):** For S500 RPM, K2 mm/rev, I3, the synchronized return requests `500*2*3=3000 mm/min`; the downstroke requests `1000 mm/min`. With a real `GET_EXTERNAL_AXIS_MAX_VELOCITY(Z)=2500 mm/min`, development's interpreter condition is `3000>2500` and predicts a G33.1 error *before* RIGID_TAP; stable's converter does not perform this test. Neither prediction establishes actual motor, drive, spindle, or axis capability.

**D2, G96 CSS radius selection (SOURCE-CONFIRMED call difference; physical result INFERENCE):** For a coordinated X-inward G33.1, development checks `fabs(current_x)` while its neighboring G33 code checks `min_abs_over_range(current_x,end_x)`. Under an illustrative no-cap metric CSS formula S60 m/min, start X20 and end X10, the checker’s start-only RPM is `60000/(2π*20)=477.5`, versus `954.9` at X10. At K2/I1, the implied required axis rates are ~955 versus ~1910 mm/min. A hypothetical X-axis limit of 1500 would pass the start-only check and fail an end-radius check. **Caveats:** the numeric illustration assumes X values correspond to the radii used in this simplified checker, no G96 D or spindle INI cap, and a fully X-directed move; installed G7/G8, offsets, CSS origin and actual motion speed need separate verification. Do not assert a reproduced runtime overspeed.

**Additional limit:** G33.1 intentionally leaves spindle speed override active in the inspected development source; commanded-S preflight does not prove the live spindle speed/override or acceleration envelope. `I` is a commanded reverse-speed multiplier, not a measured achieved speed.
