## IO05 durable result

The representative 7I77 servo analog command is descriptor-driven Smart Serial, not generic HostMot2 PWMGen. Pinned `sserial.c` creates signed/unsigned numeric HAL objects and scaling/limit parameters from remote process descriptors. In `hm2_sserial_write_pins()`, writable numeric fields are clamped to min/max, normalized by `scalemax`, converted to the descriptor bit width, and packed in descriptor order into `chan->write[]`. Writable booleans use the same descriptor walk, so an analog-enable-like field shares the process-data image when the remote descriptor makes it writable; exact field offsets remain remote descriptor data.

The production state machine can withhold a fresh command while HAL still displays the requested value: an uncleared previous Do-It causes fault accumulation and an ignored command/early return, while persistent faults can stop the Smart Serial port in state 10 until `run` is cycled low.

Stock `hm2_test` cannot provide useful IO05 runtime evidence because reads come from an unchanging compiled-in register image and writes are discarded. A mutable fake Smart Serial remote with descriptor discovery, mutable command/status state, and write capture is therefore promoted to **2000/HIGH**, explicitly as host-path synthetic verification only.
