## 3800-S1 — automatic saw / feeder deep-pass result

The Marvel V10A chronology supplies a concrete commissioning failure:

- hydraulic shuttle position was measured with a linear encoder;
- the mechanism oscillated/jumped around target under ordinary bang-bang hydraulic control;
- after appearing to reach target, hydraulic leakage allowed the shuttle to continue creeping.

Preserve:

`encoder position in tolerance != stock stationary/stable`.

A cut authorization therefore needs whatever the real machine can defensibly establish for:

`feed target reached -> feeder stopped/stable -> clamp ownership transferred/proven -> saw ready -> cut`.

Do not promote a timer to physical proof without evidence.

## 3800 sequencing — ClassicLadder source result

Pinned LinuxCNC source establishes:

- `classicladder.0.refresh` executes in a realtime HAL thread, but rung scans are limited to no faster than 1 ms;
- scan ordering is HAL inputs -> ordered ladder/sequential sections -> HAL outputs;
- section order is behaviorally significant;
- Sequential/Grafcet transitions can cascade repeatedly in the **same scan** when downstream conditions are already true, bounded by a 50-loop guard;
- the normal ClassicLadder STOP/RUN toggle does not invoke `PrepareSequential()`;
- when ClassicLadder is STOPPED, `hal_task()` skips input sampling, logic evaluation and output writes; previously written HAL outputs are not generically cleared by the ladder STOP;
- restarting therefore resumes retained ladder/SFC state rather than physically reconciling the cell.

Preserve:

**ClassicLadder STOP != safe output state != cycle reset.**

For real automation, cycle-step state, actuator command, physical witness, fault/recovery state, manual/recovery authority and safe-output gating must remain distinct.

## Cross-machine feeder evidence

The inspected pick-and-place implementation gives a second material-handling pattern:

`M201 supervisory pickup -> M161 userspace feeder request -> ClassicLadder feeder logic`.

`M161.txt` selects one of 48 feeders by writing rack-select bits, pulses one `classicladder.0.in-N` TRUE then FALSE, and exits. It contains no completion wait or acknowledgement. `M161 returned` therefore proves only request injection, not feeder advance, part-present state or realtime event consumption.

This complements the Marvel failure:

- Marvel: physical motion can continue after a nominal position result;
- PnP: software request can finish before any demonstrated physical completion.

First reusable 3800 transaction rule:

`fresh request -> deterministic actuator sequence -> physical completion/stability -> fresh acknowledgement -> next cycle`.

## 3800-F1 — extra-joint feeder authority source result

Pinned official documentation and source now establish the native extra-joint contract:

- an extra joint participates in LinuxCNC homing but is excluded from kinematics;
- after homing, command authority transfers to `joint.N.posthome-cmd`;
- the post-home Motion path directly maps `posthome-cmd + motor_offset` to `joint.N.motor-pos-cmd`;
- normal motor-position feedback is not used by that post-home extra-joint command path;
- an independent planner/controller is therefore required.

The shipped simulator uses `limit3` for that independent planning and connects `joint.N.homed -> limit3.enable`.

Pinned `limit3` source adds an important enable semantic:

- enabled: output tracks input under position/velocity/acceleration constraints;
- disabled: target becomes zero and the output **returns toward zero under those constraints**;
- disabled therefore does not mean `hold current position`.

Preserve: **extra-joint planner enable semantics must be deliberately engineered for the feeder.** The shipped simulation's `homed` enable wiring is an example, not a complete automatic-cycle/machine-safe-state permissive.

First decision rule:

- coordinated axis — mechanism participates in toolpath geometry;
- extra joint — homed independent point-positioning outside kinematics;
- HAL/ClassicLadder state mechanism — primarily discrete/sequence-owned actuator;
- external PLC/drive controller — substantial independent automation or plant control;
- second LinuxCNC instance — genuinely independent concurrent coordinated CNC channel.

Mechanism position still does not prove workpiece position or clamp ownership.

## 3800-I1 — indexer position-versus-lock source boundary

Pinned `carousel.comp` is transferable as an indexed-position mechanism. It supports multiple feedback encodings, homing/index search, bidirectional approach, slow alignment, debounce and reverse/hold behavior.

Its completion output `ready` means **carousel in-position**.

It does not provide a universal external mechanical-lock/clamp proof. Therefore a production indexer that has a separate lock mechanism needs an outer contract such as:

`safe-to-index -> unlock command -> unlock proof -> move -> carousel.ready -> lock command -> lock proof -> process authorization`.

Do not equate station code, `strobe`, debounce or `carousel.ready` with fixture/workpiece/mechanical-lock state unless the actual mechanism establishes that relationship.

## Preserve these rules

- mechanism position != workpiece position;
- encoder in window != mechanism stable;
- command returned != actuator completed;
- request pulse issued != realtime event consumed;
- extra-joint position command != workpiece-position proof;
- `limit3.enable=0` != hold current position;
- indexer in-position != mechanical lock proof;
- software sequence step != physical state after interruption;
- ClassicLadder STOP != output-safe state;
- Grafcet step adjacency != guaranteed scan/dwell separation;
- userspace HMI/job-list authority != deterministic fast-I/O authority;
- one LinuxCNC coordinated planner != a general simultaneous multi-channel transfer controller;
- ordinary LinuxCNC/HAL logic != safety-rated control without separate evidence.
