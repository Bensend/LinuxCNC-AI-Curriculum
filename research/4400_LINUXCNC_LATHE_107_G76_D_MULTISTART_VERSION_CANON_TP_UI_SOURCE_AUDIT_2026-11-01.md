## Version-specific interpreter acceptance

**Stable v2.9.10:** `read_d` parses a real D word, but `Interp::check_other_codes` allows D with G41/G42, G70/G71/G72 or G96—not G76. Thus `G76 ... D180` is rejected by the ordinary block validation path; stable G76 `threading_pass` has no angle argument. Stable official G76 syntax has no D.

**Pinned development:** `check_other_codes` adds G33 and G76 to D consumers. `convert_threading_cycle` calculates `angle_offset = fabs(block->d_number_float)` when D is supplied, otherwise zero. It passes the angle to `threading_pass` and the main synchronized pass. The documentation describes D0/D180 for two-start and D0/D120/D240 for three-start threads, and warns D450 is not reduced to D90: the former waits one additional revolution. **These are source/docs behavior contracts, not a verified threading result.**

## End-to-end execution chain and thread ownership

1. **Interpreter (userspace):** `read_d` → `check_other_codes` → `convert_straight(G76)` → `convert_threading_cycle` → `threading_pass`. G76 still requires a turning selected spindle and valid I/J/K; 3200 machine must distinguish G7 diameter from G8 radius values.
2. **Canonical / Task (userspace):** `START_SPEED_FEED_SYNCH(spindle,pitch,false,angle)` flushes buffered segments and appends `EMC_TRAJ_SET_SPINDLESYNC` with `angular_offset_degrees`; Task forwards to `emcTrajSetSpindleSync`.
3. **Motion command (realtime command consumer):** `EMCMOT_SET_SPINDLESYNC` passes the value into `tpSetSpindleSync`. TP sets `pending_offset=fabs(angle)/360` revolutions. `tcSetupState` copies that into each newly queued synchronized TC segment.
4. **Realtime trajectory execution:** `tpActivateSegment` requests selected-spindle index when starting a new position-synchronized pass. After index clears, `tpSyncPositionMode` holds until the requested angle is reached, then establishes spindle-to-axis offset and tracks. The later segments of a pass continue the accumulated tracking offset. This **does not** independently establish encoder integrity, at-speed correctness or physical phase accuracy. The all-spindles at-speed gate is already covered by SPINDLE-22.

## Important exit-taper nuance — do not overclaim a failure

For L2/L3 exit taper, development `threading_pass` emits `START_SPEED_FEED_SYNCH(...,taper_pitch,0)` **without** its `angle_offset` argument (line 5977), whereas entry/main synchronization passes the D angle (lines 5959, 5966, 5971). The default fourth argument in `canon.hh` is zero, so the exit-taper TC receives `angle_offset=0`. However, `tpSyncPositionMode` applies the angle hold only after a **fresh index**; the exit segment normally continues an already synchronized pass, and the prior tracking offset persists. **SOURCE-CONFIRMED metadata difference; physical phase shift, new index wait or bad thread is NOT established.** Development `tpActivateSegment` also rejects reverse activation of synchronized segments, so do not invent a reverse-run consequence. A future disconnected trace should inspect TC angle metadata and continuity separately.
