## Mechanism and exact source locations

1. **M5 selection:** [interp_convert.cc L3498–3518](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/rs274ngc/interp_convert.cc#L3498-L3518) handles `M5 $-1` (all spindles), a specific `$n`, and no `$` (all configured spindles in this implementation). It marks interpreter spindle state stopped and queues `STOP_SPINDLE_TURNING`. [emccanon.cc L1947–1956](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emccanon.cc#L1947-L1956) flushes segments, queues `EMC_SPINDLE_OFF`, and sets canonical direction to zero. [emctaskmain.cc L2011–2014](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emctaskmain.cc#L2011-L2014) dispatches `emcSpindleOff`, which [taskintf.cc L1937–1943](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/taskintf.cc#L1937-L1943) forwards as `EMCMOT_SPINDLE_OFF`. **Do not claim that M5 clears `atspeed_next_feed` until the motion command handler is inspected.** M5 command dispatch is not physical proof of zero RPM.

2. **M19 is conditional, not an unconditional wait:** [interp_convert.cc L3518–3535](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/rs274ngc/interp_convert.cc#L3518-L3535) queues `ORIENT_SPINDLE` when R or P is present and separately queues `WAIT_ORIENT_SPINDLE_COMPLETE` only when Q is present; Q must be >0. Default spindle is 0 unless `$n` is provided. [emccanon.cc L1961–1980](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emccanon.cc#L1961-L1980) flushes segments and appends `EMC_SPINDLE_ORIENT` / `EMC_SPINDLE_WAIT_ORIENT_COMPLETE`. [emctaskmain.cc L2492–2495](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emctaskmain.cc#L2492-L2495) maps the wait message to the spindle-oriented execution state.

3. **Orientation completion is aggregated:** [emctaskmain.cc L2695–2730](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emctaskmain.cc#L2695-L2730) loops through *all configured spindles*, taking the maximum `orient_state` into a single state variable; NONE and COMPLETE end the wait, IN_PROGRESS waits until timeout, FAULTED reports error. This is **not obviously a per-selected-spindle acknowledgement** even though the canonical wait message carries `spindle`. The ordering of state enum values, fault handling elsewhere, and timeout initialization must be verified before asserting multi-spindle corner-case behavior. In particular, a NONE state in this wait path can be treated as done; it is not proof of a completed physical orientation.

4. **M6 stop is configurable:** [interp_convert.cc L5565–5655](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/rs274ngc/interp_convert.cc#L5565-L5655) rejects a missing T-selected pocket and active cutter compensation, calls `START_CHANGE`, and issues spindle stop for all spindles only when `tool_change_with_spindle_on` is false. Optional quill-up and G30 moves precede `CHANGE_TOOL`. [emccanon.cc L2065–2136](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emccanon.cc#L2065-L2136) may append an additional configured tool-change-position move and always queues `EMC_TOOL_LOAD`. This is a command sequence, **not** evidence that an ATC has physically completed or that spindle zero speed has been independently proven.

## Practical analytical oracles (not executed)
- M5 without `$` on a multi-spindle configuration should enqueue one stop per configured spindle; check command trace, not just spindle-0 GUI indication.
- M19 R90 without Q enqueues orientation but not the explicit wait message. M19 R90 Q5 adds a positive-timeout wait; Q0 is rejected.
- A Q-wait with orientation state NONE can satisfy the inspected Task state switch. Verify downstream hardware handshake before treating this as a successful physical orientation.
- M6 may be configured to leave the spindle running. Even with stop requested, the tool changer must not equate `EMCMOT_SPINDLE_OFF` dispatch with measured standstill.
- A multi-spindle orientation test should isolate each `orient_state` and observe whether the Task aggregate chooses the expected result; do not infer selected-spindle isolation from the message field.

## Reproduction and diagnostic exercise
On a **simulation only**, instrument command/status transitions for `M3 S1000`, `M5`, `M19 R90`, `M19 R90 Q5`, `T1 M6`. Compare Task state, per-spindle orientation status, and HAL spindle enable/feedback; use a fake ATC handshake and never connect the exercise to a physical actuator. Before any real-machine adaptation, trace `EMCMOT_SPINDLE_OFF`, `EMCMOT_SPINDLE_ORIENT`, `EMC_TOOL_LOAD` and `iocontrol` tool-change acknowledgement. Keep personnel safety independent of LinuxCNC command sequencing.
