## Geometry fixture 1 — Y-only state update (G90)
```ngc
G21
G90 G91.1
#<holes>=2
G0 X10 Y10
G1 Y20
G3 I5 J0
M2
```
A full circle at actual start (10,20) should have its overburn centered relative to Y20. Source filter condition only sees X for ordinary coordinate updates. Compare inserted overburn arc against a control replacing `G1 Y20` with `G1 X10 Y20`. Theoretical default 4 mm overburn radius 5 endpoint Y≈16.413 versus stale-source Y≈6.413; **analytical, not observed**. Check for interpreter arc-radius rejection separately.

## Geometry fixture 3 — zero-coordinate full circle
```ngc
G21
G90 G91.1
#<holes>=2
G0 X0 Y10
G3 I5 J0
M2
```
Compare with X0.001 control. `if self.lastX and self.lastY` fails for X0, so automatic `isHole` overburn should be omitted in the static path. Do not equate omitted overburn with no arc execution or with all hole-velocity features.

## Geometry fixture 4 — absolute arc-center J
```ngc
G21
G90 G90.1
#<holes>=2
G0 X10 Y10
G3 I15 J10
M2
```
The filter's J path calls `get_axis_value('J')` without the required `axis` argument. Capture the Python exception if reproduced; compare with `G91.1; G3 I5 J0` control. A filter exception is **not** an interpreter error or machine fault.

## Material fixture 5 — cross-unit percentage
Use an **inch** simulation configuration and these separate lines before any cutting:
```ngc
G21
(o=0, na=unit-test, ph=3.1, pd=0.1, ch=0.75, fr=3000, jh=150, jd=0)
M2
```
The temporary material is generated by the filter; inspect `PUDDLE_JUMP_HEIGHT` in the generated material file and GUI/HAL value. **Expected specification: 150 percent**, not 0.004805 (stable source arithmetic) or 5.905512 (inspected development arithmetic). Repeat with `jh=0`, `jh=200`, and reciprocal mm machine / G20. Never use these values to command a physical torch.

## Postprocessor interface review
A conservative **illustrative** QtPlasmaC cut header and sequence (not a complete runnable cut program):
```ngc
G21 G90 G91.1
G64 P0.1
M52 P1
M190 P1
M66 P3 L3 Q1
F#<_hal[plasmac.cut-feed-rate]>
G0 X10 Y10
M3 $0 S1
G1 X20 Y10
M5 $0
M2
```
The selected material 1 must exist and its settings must be correct. Official docs specify `$0` torch, `$1` scribe, `$2` spot, and ordered material/wait/feed commands. For hole overcut use `#<holes>=2` and verify filter-generated M62 P3 and M65 recovery, but [PLASMA-32](../research/4400_LINUXCNC_PLASMA_32_QTPLASMAC_OVERCUT_M62_P3_TP_TIMING_AND_FILTER_SOURCE_AUDIT_2026-10-31.md) already explains why the G-code vertex is not a measured torch-off instant. For generic DXF CAM, [CAM-38](../research/4400_LINUXCNC_CAM_38_OPENBUILDS_DXF_NESTED_INSERT_UNITS_GCODE_SOURCE_AUDIT_2026-10-31.md) requires independent units/curve verification before accepting a post.
