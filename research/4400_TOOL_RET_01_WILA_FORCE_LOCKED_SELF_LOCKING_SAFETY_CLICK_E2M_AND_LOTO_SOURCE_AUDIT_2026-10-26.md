# 4400 TOOL-RET-01 — Press-brake tool-holder retention, pressure dependency and roll-out protection
**26 October 2026 | 4000/4400 safety | Original manufacturer/OSHA documentary audit | NOT a selected-machine design or release**

## Question and novelty
When the press-brake ram has stopped, what prevents a punch/die from dropping or sliding out while an operator changes tooling? This is a *separate physical safe-state proposition* from Y1/Y2 stop/hold. Repository safety-course index and GitHub code search for `Safety-Click`, `force-locked clamping`, `E2M Guard`, and `tool retention` showed no existing dedicated source audit. Existing hydraulic HOLD, RAM support, tooling-handling, LOTO and rescue lessons are prerequisites, not proof of tool retention.

## Four separate physical propositions
| ID | Proposition | Required independent witness, not a software assumption |
|---|---|---|
| TOOL-PHY-01 | Upper punch is physically retained against gravity at rest, during handling and through relevant energy/fault transitions | Exact approved tang/holder/retainer, positive retention and independent qualified inspection/validation |
| TOOL-PHY-02 | Heavy tool cannot unintentionally roll/slide out of an open lateral path | Installed, maintained end-stop/roll-out guard and handling/support method appropriate to tool and holder |
| TOOL-PHY-03 | Y1/Y2 ram and lower die cannot create a crush/trap hazard during access | Independent ram holding/restraint, energy isolation or separately justified effective alternative protection; selected machine validation |
| TOOL-PHY-04 | A tool change cannot automatically authorize the next stroke | Guard/access clear, tool installed/retained, independent safety state restored, **fresh** deliberate start under qualified machine SRS |

**INFERENCE:** tool-retention failure can injure a person even if the ram is stationary and LinuxCNC reports ESTOP. Conversely, a retained tool does not establish safe ram, hydraulic isolation or personnel protection.

## Authority and dependencies
- **Normal control:** LinuxCNC/HAL/FPGA, CNC program, tool-location LEDs, clamp requests, setup recipes. They may command/monitor, but do not establish personnel-safety authority.
- **Monitoring/diagnostics:** pressure switch, clamp-status bit, position LED, safety PLC diagnostics if installed. Sensor truth depends on placement, failure mode and independence; `CLAMP_OK` is not a universal physical witness.
- **Safety-related control:** only a selected, designed and validated safety chain may inhibit hazardous motion/access for a defined function. No PL/SIL target or diagnostic coverage is assigned here.
- **Physical retention/energy:** tang/positive capture, clamp pins/wedges, roll-out stop, handling supports, ram restraint, hydraulic/pneumatic stored energy, electrical isolation. Stop/hold and tool retention require separate proofs.
- **Common causes:** shared 24 V, pressure/air source, mistaken tooling identity, wrong mounting, damaged retainer, wrong clamp configuration, tool weight/length, mixed OEM adapters, and removed guards. A single “healthy” controller bit cannot prove all these dependencies absent.

## Human-factors design contract
A practical safer system should make the safe path **shorter and simpler**: mechanically captive small tools where qualified, easy-to-use guarded loading and roll-out stops for heavy tooling, conspicuous compatibility markings, accessible clamps without hands beneath unsupported tools, stable support carts, and visible no-energy/hold status without false “safe” claims. If workers repeatedly remove end-stops or guards to change dies, treat that inconvenience as a design defect and revise the hardware/workflow rather than merely posting warnings. Avoid hidden “expert” bypasses and unlabeled mixed tool tangs.
