## Newly source-closed facts

### Native LinuxCNC

- synchronized `G12.1/G13.1` switching keeps interpreter/Motion kinematics state coordinated; the raw HAL switch pin is deprecated because lookahead may use stale kinematics;
- kinstype persists across Abort/program end;
- `genserkins` inverse is iterative/Jacobian-based and seed-sensitive, with explicit failure on matrix inversion or iteration exhaustion;
- realtime inverse failure/non-finite joint output sets Motion error and requests disable;
- joint soft-limit checking remains a separate downstream backstop;
- SCARA branch state is explicit and its cosine clamp creates a specific reach-boundary validation question.

### Tormach ROS2/HAL realtime bridge

At `tormach/hal_ros_control@506a3d109cb306e1d1cdb70f24440bde1159b256`:

- `hal_control_node.funct` executes `controller_manager.read -> update -> write` from a HAL realtime thread;
- the ROS MultiThreadedExecutor runs separately;
- `HalSystemInterface::read()` copies HAL feedback pins into ros2_control state storage;
- `write()` copies ros2_control command storage to HAL command pins;
- the generic bridge's activate/deactivate callbacks do not explicitly reset command pins;
- `CM_OK=0` causes the realtime function to return without a source-visible command-pin reset;
- reset behavior restarts active controllers and relies on controller activation semantics rather than directly copying feedback to command pins.

### ZA6 drive state / brake authority

At `tormach/tormach_za_ros2_drivers@b58078aac3004f3932079ea7228ab0432cf8ac18`:

- drive START/STOP is separately commanded through `hw_device_mgr` state pins and services; command issuance is not completion;
- enable waits for `state_fb == state_cmd` plus `goal_reached`, with fault and timeout handling;
- before START, `zero_error()` publishes a one-point trajectory equal to current joint feedback and waits for every observed command-feedback error to fall within 0.001 rad;
- this protects against stale initial controller position command when enabling but is not a runtime communications watchdog;
- homing manipulates Inovance drive brake-function SDO configuration, asserts per-joint home request, waits for success/error/timeout, then zeroes command error before clearing the request and restoring normal brake-function behavior;
- controller selection, controller command, drive START/STOP, brake handling and safety/STO remain separate authorities.

Thus a key part of the stale-command question is now answered for **enable-time reconciliation**, while runtime loss of controller manager / EtherCAT freshness still needs downstream tracing.
