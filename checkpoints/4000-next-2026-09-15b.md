## Working core selection

Use LiteX-CNC as the preferred working firmware baseline on a Colorlight-derived ECP5 core. This is conditional, not irreversible.

Core hardware baseline:

- ECP5-25 BG256 class;
- one GbE PHY;
- no SDRAM by default;
- SPI NOR + JTAG/sysCONFIG service access;
- dedicated oscillator rather than PHY-owned FPGA system clock;
- required 1.1 V/3.3 V rails only;
- separate protected machine power entry;
- USB-C service/program/debug only;
- no copied HUB75 field-I/O front end.

See `research/4000-firmware-protocol-comparison-2026-09-15.md`, `research/4000-litexcnc-output-watchdog-audit-2026-09-15.md`, and `hardware/4000-colorlight-core-copy-adapt-contract.md`.

## Exact next work — encoder block

1. Inspect proven open LinuxCNC/Mesa/community encoder electrical front ends, especially differential RS-422 A/B/Z receivers, termination, bias/failsafe behavior, surge/ESD protection and connector/reference-ground strategy.
2. Separate electrical signal presence from valid quadrature/index semantics and transport freshness.
3. Decide whether the base board supports differential-only or differential + single-ended encoders and whether adaptation belongs on-board or on external interface modules.
4. Define channel count, maximum edge rate, index handling, input diagnostics and failure behavior using `hardware/BLOCK_SPEC_TEMPLATE.md`.
5. Prefer a proven receiver topology and datasheet reference circuit; no simulation unless an actual analog/timing uncertainty remains.

Then proceed to digital I/O, step/dir, PWM/analog and proportional-current blocks.
