## 3700-E1 source result — closed for current breadth pass

Pinned Motion/TP source establishes:

- M52/adaptive-enable authority is separate from realtime `motion.adaptive-feed`;
- adaptive input is sampled while AF is enabled and clipped to `+-MAX_FEED_OVERRIDE`;
- magnitude scales feed while sign requests TP run direction;
- direction changes are refused while TP is moving, so the adaptive path drives scale to zero until the planner can reverse;
- reverse completion uses `tcqBackStep()` rather than normal forward queue pop, so reverse operation genuinely traverses retained trajectory segments backward;
- synchronized M62/M63/M67 changes are attached to TC segments as commanded values, not prior-state/undo snapshots;
- no reverse-specific synchronized-I/O inversion/reconstruction path was found;
- abort clears pending cached synchronized I/O and, once stopped, clears the TP queue and resets reverse state, but generic TP abort is not a physical EDM process-output reconciliation contract.

Therefore **reverse path != process-state rollback**. An EDM recovery controller must explicitly own spark/wire/flushing state rather than assuming negative adaptive feed reconstructs synchronized-output chronology.

A generic reverse/DIO lab is not required; the architecture boundary is already source-visible. Run a later lab only for timing/behavior of a concrete proposed EDM output contract.
