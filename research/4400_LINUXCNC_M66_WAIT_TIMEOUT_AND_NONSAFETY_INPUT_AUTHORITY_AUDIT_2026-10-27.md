## Four discriminating failure paths

| Scenario | Mechanism / observable normal-control result | Safety significance |
|---|---|---|
| Digital input stuck HIGH before `M66 P0 L3 Q5` | Task `WAIT_MODE_HIGH` accepts HIGH immediately; `#5399` normally 1 if still HIGH when read. **SOURCE-CONFIRMED** | HIGH level alone cannot prove a fresh physical event, correct sensor, independent guard or load retention. **INFERENCE** |
| `M66 P0 L1 Q5` with input initially HIGH | Task `WAIT_MODE_RISE` first requires observing LOW, then HIGH; `L1` differs from `L3`. **SOURCE-CONFIRMED** | Edge detection is still ordinary Task polling of motion status, not a qualified safety dual-channel/OSSD test. |
| Input never satisfies condition before Q deadline | Task sets `input_timeout=1` and execution state DONE; subsequent `#5399=-1`. **SOURCE-CONFIRMED** | **Timeout does not automatically terminate the G-code program**; following program logic must explicitly reject it. Neither rejection nor G-code abort proves a hydraulic/drive final element safe. |
| Input changes again between Task satisfaction and interpreter read | `GET_EXTERNAL_DIGITAL_INPUT` reads current `emcStatus->motion.synch_di[index]`, not a latched event-value field. **SOURCE-CONFIRMED implementation** | A different `#5399` value is possible if the sampled input changes during this interval (**INFERENCE**, not runtime-observed). Never treat `#5399` as a physical safety-state witness. |

## Practical architecture and human factors

Use M66 for **ordinary production sequencing only**, e.g. wait for an auxiliary clamp-status input before the next commanded non-hazardous step. The G-code owner must explicitly handle `#5399=-1`, mismatched level, stale/implausible input, timeout cleanup, and a fresh operator restart decision. An easily visible `waiting / timed out / not-ready` state and an accessible normal recovery path reduce pressure to jumper sensors or disable timeouts. A normal input indicating 'clamped' does not establish mechanical tool retention.

For a press brake, **do not** allocate AKAS muting, independent safe speed, Y1/Y2 ram stopping, load holding, guarding, emergency stop, or personnel-access authorization to `M66`, `#5399`, ordinary FPGA feedback or LinuxCNC HAL. Independent safety logic and physical final elements must establish and validate those propositions. The actual OpenPressBrake Pilz/AKAS program and hydraulic safe state remain **UNKNOWN**; see [AKAS-M exact source audit](4400_AKAS_LCII_M_PILZ_MUTING_SLOW_SPEED_OVERTRAVEL_AUTHORITY_AUDIT_2026-10-27.md) and [restricted evidence card](../safety-course/4400_AKAS_M_01_RESTRICTED_PILZ_MUTING_OVERRUN_EVIDENCE_DELTA_2026-10-27.md).

## Adversarial review of an actual upstream simulation program (no execution)

The [VMC tool-change sample](https://github.com/LinuxCNC/linuxcnc/blob/c9a5a0a5034177c8db64cb44abf14d4f2eb166f7/configs/sim/axis/vismach/VMC_toolchange/toolchange.ngc#L11-L24) uses `M66 P2 L3 Q5` and then `O104 if [#5399 LT 0]` to reject timeout; later [lines 63–70](https://github.com/LinuxCNC/linuxcnc/blob/c9a5a0a5034177c8db64cb44abf14d4f2eb166f7/configs/sim/axis/vismach/VMC_toolchange/toolchange.ngc#L63-L70) wait for `tool-released=false` using L4 and check only `#5399 LT 0`. **SOURCE-CONFIRMED** this is a simulation example that checks the timeout sentinel but does not compare the final returned input level with the expected level. Because [`GET_EXTERNAL_DIGITAL_INPUT`](https://github.com/LinuxCNC/linuxcnc/blob/c9a5a0a5034177c8db64cb44abf14d4f2eb166f7/src/emc/task/emccanon.cc#L4117-L4128) reads current motion status **after** the wait, a rapid input change could yield 0 after a satisfied L3 wait or 1 after a satisfied L4 wait. In those hypothetical cases `#5399 LT 0` would not reject the mismatch (**INFERENCE**, not observed). For ordinary sequencing, checking both **timeout** and **expected returned state**, plus ensuring sensor freshness/stability as required by the process, is more defensible than a timeout-only check. Even those checks remain non-safety software; do not treat the upstream simulation as a machine safety design or claim a proven upstream defect without a runtime reproduction.
