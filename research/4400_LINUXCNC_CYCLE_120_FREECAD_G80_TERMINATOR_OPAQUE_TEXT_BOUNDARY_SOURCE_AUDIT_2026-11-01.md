# CYCLE-120 — FreeCAD's G80 terminator protects Path.Commands, not opaque G-code text

**Status:** 4000 LinuxCNC + 3100/3400 CAD/CAM integration; NON-GRADUATED. **Audit:** 2026-11-01. **Pinned:** FreeCAD `24ea8589aa8676049f7fe53ca9d1d1c398c38d26` (the same source revision as CYCLE-118), stable LinuxCNC v2.9.10 `86cdca76fa2a36274c432caa21952b23c267989a` and development `06864e23559e70463fc7112d5ce77138bcbc288c` from [CYCLE-119](4400_LINUXCNC_CYCLE_119_G17_G18_G98_INITIAL_LEVEL_STICKY_AXIS_SOURCE_AUDIT_2026-11-01.md). **SOURCE-CONFIRMED conditional; TEST-CONFIRMED none.**

## Why this is an incremental cross-project result

CYCLE-119 found that LinuxCNC G17→G18 does not itself cancel an active G81 or recapture G98 initial level. That is a controller-side source path, **not evidence that stock FreeCAD emits the vulnerable sequence**. This audit follows the current FreeCAD producer to determine whether it already inserts G80 and where that automatic guarantee ends. CYCLE-118 covered expanded versus native G73/G83 geometry; it did not inspect the G80 terminator or opaque-text boundary.

## Pinned FreeCAD source and execution path

1. The [LinuxCNC post default preamble](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/Path/Post/scripts/linuxcnc_post.py#L86-L99) includes `G17 G54 G40 G49 G80 G90`; postamble and safety block also include G80. This establishes *default template strings*, not the emitted file for every customized job.
2. [`Processor._expand_canned_cycles`](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/Path/Post/Processor.py#L1411-L1428) iterates each postable's `item.path`, detects drill commands and calls `PostUtils.cannedCycleTerminator(item.path)`. [`Processor` expansion order](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/Path/Post/Processor.py#L2860-L2886) calls this terminator **before** `_expand_translate_drill_cycles`. Therefore native and expanded ordinary drill Path.Commands pass through the terminator first.
3. [`cannedCycleTerminator`](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/Path/Post/Utils.py#L382-L482) tracks `cycle_active`. For any **non-cycle Path.Command** while active—including a Path.Command named G18—it inserts `G80` before the new command. It also terminates on changed drill parameters or retract mode and appends G80 at path end. It preserves an explicit G80 without duplicating it. Existing [`TestPostCore`](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/CAMTests/TestPostCore.py#L225-L322) defines cases for changed cycles, G98/G99 transitions, and G80 insertion; **test sources inspected, not run**.
4. The boundary: `_expand_canned_cycles` processes only `item.path`. [`Processor._make_postable`](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/Path/Post/Processor.py#L2508-L2539) can instead create `item_type="str"` with `path=None` for opaque text. [`_convert_item_commands`](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/Path/Post/Processor.py#L2415-L2440) copies those raw lines to output, resets its machine-state cache and calls `addGcodeText`. It does **not** call the canned-cycle terminator on the raw string. The same processor explicitly describes these as opaque text postables. Thus the automatic G80 guarantee is **not universal for raw embedded G-code**.
5. [`DrillCycleExpander.expand_command`](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/Path/Post/DrillCycleExpander.py#L65-L126) handles G98/G99 and filters G80 after expansion; its own contract explicitly states it **does not support modal repeat-on-move until G80 or L repeats**. Do not assume a handwritten `G81 ...` followed by `X...` behaves identically when translated into explicit G0/G1.
6. [`linuxcnc_post._convert_modal_command`](https://github.com/FreeCAD/FreeCAD/blob/24ea8589aa8676049f7fe53ca9d1d1c398c38d26/src/Mod/CAM/Path/Post/scripts/linuxcnc_post.py#L347-L362) suppresses G80/G98/G99 **only when annotated as rigid tapping**, whose G74/G84 conversion path uses G33.1. This exception must not be generalized to ordinary G81.

Relevant FreeCAD inspected Git blobs: `Processor.py` `df5d105361699d3828094bc297073e08c6fef083`; `Utils.py` `fbf82c2fcaf0840200399c2aead7680be0a76250`; `linuxcnc_post.py` `f686609e4e815bb7ff5fecd709d315e5a0b315fc`; `DrillCycleExpander.py` `17c89aad7a11b7d299e2aca523bd0cde2245d057`; `TestPostCore.py` `8d225dfcc54042596373c267d3fc7c65e254cba5`.

## Discriminating handoff, not a claim of a stock FreeCAD bug

| Source representation | FreeCAD's G80 termination path | CYCLE-119 cross-plane risk |
| --- | --- | --- |
| Ordinary drill `Path.Command("G81", ...)` followed by `Path.Command("G18")` in the **same** processed path | `cannedCycleTerminator` inserts G80 before G18 | This specific retained-cycle sequence is prevented at the postable-command stage, assuming no later text modification |
| Ordinary drill `Path.Command` at end of a processed path | Terminator appends G80 | Retained G81 normally prevented at that boundary |
| Opaque string containing `G81 ...\nG18\nX10 Z10` | No `item.path` to process; raw string passed to output | LinuxCNC may retain G81/old Z scalar; exact emitted file and interpreter result **UNKNOWN** |
| Translated G81/G83 into explicit G0/G1 | Expander removes modal cycle commands | Controller no longer expands a native cycle; geometry must be checked in the **expanded** path |

**Source-derived example only:** If a raw G-code text block emits the CYCLE-119 sequence with no G80, the LinuxCNC parser may issue the Y20/Y-2 canonical targets described there. This audit does **not** establish that a specific FreeCAD machine, post customization, UI text block, or production job actually emits it. It also does not establish how an arbitrary postprocess hook might rewrite the resulting NC file.

## Practical integration rule and evidence debt

Do not disable the FreeCAD G80 terminator for normal Path.Commands. For any **opaque G-code block, custom postamble/preamble, injected script or externally concatenated NC**, run a final **text-level modal preflight** on the actual emitted file: after an active G73/G81–G89, reject a plane change without intervening G80/group-1 cancellation; also reject unqualified axis-only modal repeats if the post/expander cannot preserve their semantics. Treat a G80 in a configured preamble as only a startup reset, not a proof about later raw blocks. This preflight is a CAM quality gate, not physical guarding.

[Cross-plane CAM preflight guide](../guides/3100-4000-linuxcnc-canned-cycle-plane-transition-cam-preflight-2026-11-01.md) has the minimal controller A/B oracle. Do **not** add a large unexecuted FreeCAD test bank; reuse `TestPostCore` and `TestDrillCycleExpander` when qualified software-only execution becomes available.
