## Frozen prediction preserved

An ordinary `joint.0.homed` state established in runtime A should not be inherited by a genuinely fresh runtime B using the same unchanged INI; B should begin unhomed and be able to re-establish homed state through a new homing request. No acceptance gate is weakened by this analysis.

## What the run established

The fixture launched runtime A successfully. The initial `joint.0.homed` value was `FALSE`, and the scripted homing request caused it to become `TRUE`. Gates A/B therefore exercised the intended ordinary-homing fixture successfully.

The run then failed before any runtime-B observation. The harness sent `SIGTERM` directly to the outer `linuxcnc` launcher PID and waited 15 seconds. That launcher remained alive, producing `HARNESS_INVALID: A launcher survived orderly wait` and exit code 21. Because the independently required teardown barrier was never reached, this run supplies **no evidence** for or against homing-state persistence across a fresh runtime.

## Root-cause analysis

The harness used the wrong primary shutdown interface for this fixture.

The pinned fixture INI sets `[DISPLAY] DISPLAY = linuxcncrsh -n RuntimeTestMachine`. LinuxCNC's documented `linuxcncrsh` protocol has a `shutdown` command that, after HELLO and control enablement, asks LinuxCNC to shut down; the documentation specifically notes automatic LinuxCNC shutdown when `linuxcncrsh` is the configured DISPLAY. The fixture therefore already exposes a purpose-built shutdown path.

Directly sending TERM to the wrapper enters launcher cleanup asynchronously and makes the experiment depend on shell cleanup timing rather than the fixture's normal control path. That is exactly the kind of lifecycle ambiguity S07 is intended to avoid.

## Material harness correction

Commit `c8294d613924b3277611fbb2ae4a89c98a52eea7` changes Gate C to:

1. negotiate a fresh linuxcncrsh session;
2. obtain control with `set enable EMCTOO`;
3. issue protocol command `shutdown`;
4. require the launcher PID to disappear;
5. only then require both TCP port 5007 and `joint.0.homed` to disappear before runtime B may start.

The runtime-B cleanup path also prefers the protocol shutdown command, but its cleanup behavior is not used as evidence for the frozen A→B persistence prediction.
