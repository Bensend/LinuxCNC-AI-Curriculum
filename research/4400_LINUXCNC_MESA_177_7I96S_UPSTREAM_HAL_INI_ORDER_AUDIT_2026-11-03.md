## Exact schedule in the inspected file
```hal
addf hm2_[HOSTMOT2](BOARD).0.read  servo-thread
addf motion-command-handler       servo-thread
addf motion-controller            servo-thread
addf hm2_[HOSTMOT2](BOARD).0.write servo-thread
addf estop-latch.0                servo-thread
```
The INI selects `SERVO_PERIOD=1000000` ns and `HALFILE=hm2-stepper-eth.hal`; `[HOSTMOT2]` selects `DRIVER=hm2_eth`, `BOARD=7i96s`, `BOARD_IP=192.168.1.121`, `CONFIG="num_encoders=0 num_pwmgens=0 num_stepgens=3"`. HAL loads `[KINS]KINEMATICS`, `motmod`, `hostmot2`, then the configured board driver before scheduling. The address is an **upstream example**, not an instruction to contact hardware.

**One-cycle causal graph (SOURCE-CONFIRMED ordering; timing effects INFERENCE):**
1. `hm2_7i96s.0.read` samples device-facing feedback into HAL.
2. `motion-command-handler` then `motion-controller` operate on the available signals.
3. `hm2_7i96s.0.write` transmits current stepgen commands/enables.
4. `estop-latch.0` evaluates `watchdog.has_bit` and `iocontrol.0.user-request-enable` **after** the board write.

The X/Y/Z `joint.N.motor-pos-cmd` connect directly to `stepgen.0N.position-cmd`, and `stepgen.0N.position-fb` connects to `joint.N.motor-pos-fb`. No PID `addf` appears. `STEPGEN_MAX_VEL=12` and `STEPGEN_MAX_ACC=24` exceed each joint's `MAX_VELOCITY=10` and `MAX_ACCELERATION=20`; the file explicitly documents this margin. This is **stepgen position mode**, not an independently sensed encoder/closed-loop axis: the configured `num_encoders=0` and source of `position-fb` are important limitations.

## Non-obvious order boundary
The estop latch appears **after** `hm2.write`. If a newly sampled watchdog fault causes `estop-latch.0.ok-out` to change, the IO-side enable input may see the updated value later in the servo cycle than the board write. Whether this actually delays drive disable, and by how much, depends on the separate IO/task/HostMot2 consumers; it is **INFERENCE/UNKNOWN**, not an asserted physical fault. Moreover `watchdog.has_bit` is wired to `fault-in`; its polarity and the watchdog pin semantics must be verified before treating this as a valid safety chain. The example itself says it is a basic estop loop including only the hostmot watchdog. **Never treat this example as independent personnel-safety authority.**
