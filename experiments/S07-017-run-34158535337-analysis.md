## Root cause of the failed oracle

Gate C implemented HAL-pin disappearance as failure of:

```sh
halcmd show pin joint.0.homed
```

That is not a valid existence oracle. At the pinned revision, `src/hal/utils/halcmd_commands.cc::do_show_cmd()` dispatches `show pin` to `print_pin_info(...)` and returns `0` for every recognized `show` type regardless of whether the pattern matched an object. A non-existent matching pin can therefore produce an empty/header-only listing while `halcmd show pin ...` still exits successfully.

The observed `hal-pin-gone=0` consequently does **not** establish that `joint.0.homed` survived teardown. It only establishes that the recognized `show pin` command itself returned success.

This is a harness-oracle error, not a LinuxCNC state-integrity result.
