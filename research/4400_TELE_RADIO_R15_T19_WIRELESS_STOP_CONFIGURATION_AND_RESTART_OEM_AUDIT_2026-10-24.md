## Source-confirmed boundaries, exact model and edition
- **DOC-CONFIRMED, R15 printed p.13:** specified T19-02/R15 combination is described as **EN ISO 13849-1:2015 PLd category 3 for the radio STOP function**. Manufacturer reports **maximum safety-stop response time 500 ms** for that subsystem. This is **NOT** a selected machine's stopping time, distance, ram holding, or achieved whole-machine PL; the OEM expressly requires correct end-user installation and calculation of other subsystems.
- **DOC-CONFIRMED, R15 printed p.14:** the claimed configuration requires *continuous radio mode*, all relays OFF on link loss, **radio-link timeout <=500 ms**, login/logout enabled, unique transmitter ID (Custom ID OFF), and **Require start command ON**. This is a product-specific parameter limit, **not** a generic allowed stop time.
- **DOC-CONFIRMED, R15 printed p.15:** Require start ON prevents receiver stop relays from activating automatically after a receiver power interruption while the transmitter is still active; if OFF, receiving packets can re-activate stop relays without a new transmitter button press and the receiver is **NOT PLd compliant** under this documented configuration. The manual describes a new start packet after >6 minutes out of range; that is a product-specific radio-session rule, **not** authorization to start hazardous motion.
- **DOC-CONFIRMED, R15 printed p.41:** operating mode 5 is *discontinuous* and the OEM explicitly states that it **cancels the PLd-classified STOP function**. Therefore changing operating mode is a safety-impacting configuration change even when normal jogging still appears functional.
- **DOC-CONFIRMED, R15 printed p.31:** login/logout deactivation also makes the documented receiver configuration not PLd compliant. Multiple transmitters may be registered, but the exact login/session policy controls which may operate. A receiver LED indicating PLd configuration is **configuration evidence only**, not proof of final-element opening, independent machine stopping or safe rearm.
- **DOC-CONFIRMED, T19 printed p.19:** the OEM's shift functional check includes the stop button, stop function and *battery removal*; performed without a load and with unexpected motion made harmless. **Never interpret this as permission to remove batteries while people are exposed**. It is a controlled integration/commissioning check requiring qualified risk assessment.
- **DOC-CONFIRMED, T19 printed pp.20–22:** a transmitter may remain **logged in** after switch-off. Logout needs matching receiver/transmitter settings and radio link; an already logged-in unit can block another operator. A lost transmitter replacement/logout procedure changes ownership and must not silently restore motion.
- **DOC-CONFIRMED, R15 printed p.15:** receiver stop relays are the safety-related output interface; programmable ordinary function relays, ordinary link-status bits and any LinuxCNC HAL/GUI indicators are not automatically qualified personnel-safety outputs.
- **DOC-CONFIRMED, T19 printed p.12:** transmitter is specified PLd Cat3 for STOP only. It does not classify every direction button, joystick, zero-position check, operating mode or machine final element as PLd.

## Failure-path and human-factor analysis (INFERENCE; not physically tested)
| Scenario | Why a green UI can mislead | Safe architecture question |
|---|---|---|
| Link interrupted or transmitter battery fails | LinuxCNC may retain last normal command; radio receiver can drop safety stop relays | Do independently wired final elements arrest the actual hazardous motion and hold gravity loads, without trusting retained software commands? |
| Receiver power brownout while transmitter remains active | If Require start disabled, radio STOP relays may reenergize when packets return | Does a **separate machine** rearm + fresh local cycle start prevent automatic motion, even if radio STOP relays become eligible? |
| Operating mode 5 selected for convenience | Normal button control may work, but documented PLd STOP function is cancelled | Can mode changes be locked, identified, revalidated, and kept out of operator convenience settings? |
| Registered transmitter stolen/lost or switched off | Radio ownership may remain logged in; operator sees ambiguous authority | Are pairing, logout/replacement, key custody, visible ownership and fresh start enforced? |
| Receiver's PLd status LED OFF | OEM indicates a compliant configuration, not the physical circuit state | Have exact terminals, final elements, wiring, response and load-hold been separately witnessed? |
| Operator can move out of line of sight | Wireless convenience encourages blind command | Are local visibility, exclusion zones, keyed control and independent protective devices designed so correct use is easier than shortcuts? |
| Stop removes pneumatic/hydraulic holding energy | Hazard may become falling ram/workpiece instead of running motor | Is STOP safe state machine-specific and load-retentive? |
| Pendant abandoned with buttons depressed | Old demand can survive link/rearm boundary | Is neutral-state check and independent fresh deliberate start proved across every takeover and reset path? |

## Layered architecture — no safety authority migration
1. **Normal control:** pendant ordinary commands, receiver ordinary relays/CAN/USB, LinuxCNC HAL/NML/FPGA, speed/position plans. A lost radio command must be handled defensively, but that software path is **not** personnel-safety authority.
2. **Independent safety input/function:** only an exact qualified transmitter+receiver+configuration and verified stop-output path may claim the documented radio stop function. Include local hardwired accessible E-stop(s) as required by the machine risk assessment.
3. **Independent safety logic/output:** selected safety controller or validated safety relay, feedback/EDM, independent stop final elements and physical holding, including fault detection and common-cause analysis. Radio STOP relays alone do not prove the whole chain.
4. **Physical energy/holding:** drive STO/SS1 if applicable, hydraulic isolation, gravity support, electrical isolation for service. Stop is not lockout/tagout or evidence of absence of stored energy.
5. **Operator/HMI:** show paired receiver/transmitter ID, active ownership, link health and reason for inhibition; labels are **diagnostic**, not a safety function. Keep a fixed local reset/start with visibility and access control where risk analysis requires.

## Engineering verification without hazardous experimentation
**Document first:** exact transmitter/receiver model, serial, SW/firmware, wiring, safety outputs, certified stop scope, selected modes and parameters, stop-response assumptions, location/visibility, number of paired devices, loss-of-link and power-return states, final elements, gravitational loads and independent rearm.

**Qualified physical verification only after an approved isolated/remote plan:** confirm safety relay terminal changes and actual final-element withdrawal, then selected machine stop/hold and occupancy/restart behavior in nonhazardous conditions with persons outside danger zones. Include loss-of-link, battery, wrong transmitter, change-of-mode, brownout and restart. Do not use the manufacturer's 500 ms radio response as an entire machine acceptance limit.
