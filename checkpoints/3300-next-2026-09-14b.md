## Established 3300-P1 contracts

1. `plasmac.comp` is a realtime plasma process state machine spanning IHS/probing, pierce, Arc OK, pierce delay, puddle jump, cut-height transition, THC, cut-end/retract and dedicated recovery states.
2. A pre-existing float/ohmic/breakaway input is not treated as a valid fresh probe contact; sensor meaning is state/episode-qualified.
3. Ohmic probing may retry and fall back to the float switch according to configured attempt policy.
4. Arc-start failure and arc loss are separate failure classes: start uses `arc_fail_delay` / retry count; established-arc loss uses Arc OK qualification and `arc_lost_delay`.
5. THC is gated by process state and multiple qualifications; it is not continuously active merely because arc-voltage feedback exists.
6. QtPlasmaC generates external-offset count requests; LinuxCNC Motion owns the applied external-offset planner, accel/velocity allocation, insertion into Cartesian command and generic soft-limit clipping.
7. Requested, applied and nominal Z are separate surfaces. QtPlasmaC waits for applied offset convergence at pierce/cut-height transitions.
8. Disabling eoffset enable does not itself clear an already-applied offset. Cleanup requires explicit return/clear/machine-cycle behavior.
9. QtPlasmaC maintains process-local Z offset bounds in addition to Motion's generic net soft-limit/eoffset-limited protection.
10. Normal end, MAX_HEIGHT, END_JOB and cut-recovery paths actively reconcile external offsets rather than assuming logical state transitions imply physical/offset cleanup.

## 3300-P3 current evidence

Production plasma authority chain is now explicitly separated:

`CAD -> CAM/process intent -> postprocessor G-code/material commands -> QtPlasmaC G-code filter -> LinuxCNC interpreter/trajectory -> plasmac realtime state -> synchronized outputs/eoffsets -> physical process feedback`.

Established boundaries:

- `M190 Pn` is a material-change request; documented workflows wait for confirmation with `M66 P3 ...` before relying on the active material feed.
- standard QtPlasmaC cut programs do not own process Z; the filter normally removes cut-program Z and the realtime process controller owns IHS/pierce/cut/retract through external offsets.
- `M62/M63 P2` express motion-synchronized THC disable/enable intent, but actual THC activity still requires realtime process qualification.
- `M67 E3` expresses synchronized feed reduction/restoration used for small-feature/hole strategies; it is not itself a THC command.
- `M62/M63 P3` is the synchronized torch-disable/enable surface recognized by the QtPlasmaC workflow/filter and can support overcut strategies.
- `qtplasmac_gcode.py` actively filters/validates/transforms process G-code; it is not transparent pass-through.
- Run From Line has dedicated reconstruction/recovery code and must not be modeled as jumping directly to line N with no process-state rebuilding.
- PowerMax RS485 settings/telemetry are a non-realtime communication path and are not the realtime cut-control loop.
