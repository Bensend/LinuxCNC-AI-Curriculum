# 4400-SAFE-RESTORE-01 — Automatic configuration recovery is not a safe replacement, and factory reset destroys evidence

## Frozen engineering question and predecessor reconciliation

When a safety sensor or safety controller is replaced, does automatic configuration recovery establish that the protected geometry and the physical safety function remain valid? Can a maintenance reset destroy the very active-project and fault history needed to determine what happened?

Read the existing [SAFE-PROGRAM-04 active identity / physical proof](4400_SAFETY_PROGRAM_IDENTITY_FPSC_EXAMPLE_PILZ_CRC_VALVE_FEEDBACK_AND_BACKFEED_SOURCE_REVIEW_2026-10-27.md) and [SAFE-PROGRAM-05 model-specific read-only evidence](4400_PNOZMULTI_CLASSIC_V10_VS_PNOZMULTI2_V11_READ_ONLY_EVIDENCE_ACQUISITION_AUDIT_2026-10-27.md) first. Those already establish active application versus workstation file, CRC ≠ machine validation, correct tool/privilege, and the need to revalidate after change. The **incremental exact OEM discriminators** here are: (a) SICK Flexi Soft ACR applies to specified **EFI sensors**, explicitly *not* Flexi Soft CPU devices; (b) a replacement FX3-MOC1 may require renewed position reference/teach-in; (c) SICK Flexi Compact SmartPlug behavior differs from Flexi Soft ACR; and (d) Pilz B0 factory reset deletes the project, inserted chip-card contents, error stack, program-change log and configured users. This is a maintenance/recovery source-depth addendum, **not** a new general reset competence or scored exam.

## Four separate authority layers (must all remain explicit)

1. **Normal LinuxCNC/FPGA/HMI:** can show alarms, motion coordinates, software HOMED and maintenance records. It cannot grant safe access or replace a safety configuration, prove sensor coverage, or own personnel safety.
2. **Independent safety controller/program:** active model, firmware, program, checksum, configuration media, sensor settings, diagnostic history and authorized rearm belong to the selected safety architecture. A CRC or recovered sensor parameter set is identity evidence, not a physical acceptance test.
3. **Safety-related final elements:** verified contactors, valves, drives, interlocks and actual fault response, independent of normal commands. Device replacement can alter sensor geometry, actuator response, wiring, reference or diagnostic assumptions.
4. **Physical machine state:** independently demonstrated Y1/Y2 stop and gravity-load holding, actual guarding/occupancy coverage, isolation of electrical/hydraulic/mechanical stored energy, and deliberate new start. A stopped controller or restored field file is not a mechanical lock.

## Practical human factors and change control

Make approved spares, labeled connectors, model-specific configuration backups, retained fault-history exports and a short return-to-service checklist available **before** a failure. Distinguish a *passive diagnostic read* from download/accept/teach-in/factory-reset/forced-output actions. Label the latter as changes needing qualified authorization and independent function revalidation. Do not ask the owner to operate an unqualified machine merely to collect logs; keep the existing seven-packet Stage A intake short. An inconvenient recovery process predictably encourages bypass or “reset until green”; design the approved path to be faster and clearer than improvised rewiring.
