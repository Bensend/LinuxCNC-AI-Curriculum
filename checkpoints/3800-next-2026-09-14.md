## 3800 sequencing — ClassicLadder source result

Pinned LinuxCNC source establishes:

- `classicladder.0.refresh` executes in a realtime HAL thread, but rung scans are limited to no faster than 1 ms;
- scan ordering is HAL inputs -> ordered ladder/sequential sections -> HAL outputs;
- section order is behaviorally significant;
- Sequential/Grafcet transitions can cascade repeatedly in the **same scan** when downstream conditions are already true, bounded by a 50-loop guard;
- the normal ClassicLadder STOP/RUN toggle does not invoke `PrepareSequential()`;
- when ClassicLadder is STOPPED, `hal_task()` skips input sampling, logic evaluation and output writes; previously written HAL outputs are not generically cleared by the ladder STOP;
- restarting therefore resumes retained ladder/SFC state rather than physically reconciling the cell.

Preserve:

**ClassicLadder STOP != safe output state != cycle reset.**

For real automation, cycle-step state, actuator command, physical witness, fault/recovery state, manual/recovery authority and safe-output gating must remain distinct.

## Cross-machine feeder evidence

The inspected pick-and-place implementation gives a second material-handling pattern:

`M201 supervisory pickup -> M161 userspace feeder request -> ClassicLadder feeder logic`.

`M161.txt` selects one of 48 feeders by writing rack-select bits, pulses one `classicladder.0.in-N` TRUE then FALSE, and exits. It contains no completion wait or acknowledgement. `M161 returned` therefore proves only request injection, not feeder advance, part-present state or realtime event consumption.

This complements the Marvel failure:

- Marvel: physical motion can continue after a nominal position result;
- PnP: software request can finish before any demonstrated physical completion.

First reusable 3800 transaction rule:

`fresh request -> deterministic actuator sequence -> physical completion/stability -> fresh acknowledgement -> next cycle`.

## Preserve these rules

- mechanism position != workpiece position;
- encoder in window != mechanism stable;
- command returned != actuator completed;
- request pulse issued != realtime event consumed;
- software sequence step != physical state after interruption;
- ClassicLadder STOP != output-safe state;
- Grafcet step adjacency != guaranteed scan/dwell separation;
- userspace HMI/job-list authority != deterministic fast-I/O authority;
- one LinuxCNC coordinated planner != a general simultaneous multi-channel transfer controller;
- ordinary LinuxCNC/HAL logic != safety-rated control without separate evidence.
