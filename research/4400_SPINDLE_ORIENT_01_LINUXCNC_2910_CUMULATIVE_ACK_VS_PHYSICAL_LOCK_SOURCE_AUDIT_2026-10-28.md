# 4400-SPINDLE-ORIENT-01 — LinuxCNC M19 position acknowledgment, cumulative samples, and physical spindle restraint
**2026-10-28 | 4000 safety/source depth | NON-GRADUATED | no runtime or physical test**

## Question and exact evidence
**Can M19 success, `spindle.N.is-oriented`, `spindle.N.locked`, `spindle.N.brake`, or `spindle.N.at-speed` establish that a spindle is physically motionless, mechanically locked and safe for toolchanger/service access?** **No.** These are ordinary LinuxCNC motion/HAL signals and commanded states; none is, by itself, a validated independent safety function. This audit adds a previously untraced **source-level cumulative-sample acknowledgment** mechanism to the prior [BAR-02 Haas M19 versus physical blocking audit](4400_HAAS_AD0021_M19_ORIENTATION_VS_SPINDLE_PHYSICAL_BLOCK_SERVICE_AUDIT_2026-10-25.md) and [ATC-01 tool-retention module](../safety-course/4400_ATC_01_TOOL_RETENTION_DRAWBAR_PNEUMATIC_RELEASE_AND_SERVICE_MODULE_2026-10-25.md). It does **not** claim M19 was installed on OpenPressBrake.

## Source execution path (normal control only)
1. **M19 request:** `command.c` lines approximately 1656–1710 handle `EMCMOT_SPINDLE_ORIENT`: set `orient_state=IN_PROGRESS`, commanded spindle speed/direction to zero, **brake command to 0 (release)**, `spindle_on=0`, clear `spindle_locked`, set `spindle_orient=1` and angle/mode. `spindle_on=0` is not proof that the separate orient PID cannot command rotation.
2. **Reference example:** `orient.comp` uses an encoder `position` input, target angle, and a positive `enable` edge. It calculates a position command for the ordinary PID. On that edge it resets `debounce=0`; on enabled subsequent invocations it computes `poserr=(position-command)*360` degrees.
3. **Crucial exact expression:** `debounce += (fabs(poserr) < tolerance && debounce <=100);` followed by `is_oriented = (debounce > 100);` in `orient.comp` around lines 94–95. **The counter increments on in-tolerance invocations but does not decrement/reset on out-of-tolerance invocations.** This is a cumulative count, not a requirement for 101 **consecutive** in-tolerance samples. After it reaches 101, the ordinary `is-oriented` output can remain TRUE even when the *current* position error is out of tolerance, while the component remains enabled. When `enable` becomes FALSE, `is_oriented` clears; a new positive enable edge resets the counter. There is **no measured velocity term** in this decision. This conclusion is static SOURCE-CONFIRMED logic, **not a runtime demonstration or measured machine fault**.
4. **Motion consumes acknowledgment:** `control.c` around lines 510–539, while `spindle_orient` is TRUE, checks nonzero `spindle_orient_fault` first; otherwise TRUE `spindle_is_oriented` clears `spindle_orient`, sets the `spindle_locked` HAL **output**, internal `locked=1`, `brake=1`, and `orient_state=COMPLETE`. It does **not** inspect a mechanical brake engagement sensor in this path. The name `locked` is therefore an ordinary state indication, not a physical lock witness.
5. **Commanded brake versus measured brake:** `control.c` later publishes `spindle_brake` from `spindle_status.brake`; `motion.c` exports `spindle.N.brake` as **HAL_OUT**. This is a request to external hardware, not feedback proving brake engagement, holding torque, or stop time. `command.c` M3/M4/M5 transitions can clear the orient/locked state.
6. **Unwired at-speed trap:** `motion.c` around lines 729–735 exports `spindle.N.at-speed` as **HAL_IN** and initializes it to **1**. Thus a TRUE at-speed signal can be a default for an unwired machine. It is a normal feed-interlock/status input, not a safety-rated zero-speed witness. It must not be conflated with orient-complete or independent spindle-safe-stop monitoring.

## Deterministic paper discriminators (not tests or grading)
- **Intermittent crossing:** 100 qualifying in-tolerance updates interspersed with 100 nonqualifying updates leave `debounce=100`; one further qualifying update raises `is-oriented`. This follows the exact addition expression; **no 101-sample continuous dwell** was required.
- **Stale/frozen feedback:** If encoder position reports the target while actual shaft movement differs, the normal component can accumulate qualifying updates. This is an **INFERENCE conditional on a feedback fault**, not evidence that a particular encoder has failed.
- **After threshold:** An out-of-tolerance sample does not lower `debounce` from 101 while enabled; `is-oriented` can still be TRUE. Whether Motion consumes that particular sample depends on HAL scheduling and wiring; no servo period or real-world duration is inferred.
- **Brake command not brake contact:** `spindle.N.brake=TRUE` and `spindle.N.locked=TRUE` can coexist with unverified physical engagement or retention. Neither is a brake-contact witness.
- **At-speed default:** An unwired TRUE input cannot prove zero RPM, successful stop, or safe door unlock. No safety release may be derived from it.

## Authority and machine-release design review
| Layer | Valid proposition | Invalid shortcut |
|---|---|---|
| LinuxCNC Task/M19, motion, HAL `orient`, `locked`, `brake`, `at-speed` | Ordinary positioning requests, state and diagnostics | Safety-rated zero speed, physical lock, service isolation or guard release |
| Normal encoder/PID and drive | Process alignment and troubleshooting | Independent personnel-protective speed/standstill monitoring without qualification |
| Independent safety-related control | Selected machine's validated protective-device logic, safety stop, access permission, fault and restart behavior | Reusing the normal `is-oriented` bit as a safety verdict |
| Physical mechanisms | Validated spindle coast-down, mechanical restraint/brake engagement and holding, tooling capture, power isolation | A commanded brake output or M19 status standing in for measured restraint |

**Incremental physical witness:** on a selected machine, qualified reviewers must identify the actual spindle drive, encoder/feedback provenance, safety-rated or independently qualified standstill/guard-unlock conditions where required, physical brake/lock design and monitoring, actual stop/coast/hold behavior, tool capture, isolation of stored energy, and deliberate fresh restart. The witness must be specified by a machine-specific hazard assessment and qualified plan; **no physical tests are authorized here**. A guard must remain effective until hazardous motion has actually ceased; maintenance needs task-specific physical isolation and approved restraint, not just software orientation.

## Task/NML completion boundary (second source path)
**SOURCE-CONFIRMED** LinuxCNC `v2.9.10` `src/emc/task/emctaskmain.cc`, blob `7292a172023a5b42b023447c2458cb766c93fc9b`, [tag source](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emctaskmain.cc): `EMC_SPINDLE_WAIT_ORIENT_COMPLETE_TYPE` establishes a Task deadline (`taskExecDelayTimeout`) and waits in `EMC_TASK_EXEC_WAITING_FOR_SPINDLE_ORIENTED`. Around lines 2695–2732, the wait scans `emcStatus->motion.spindle[n].orient_state` and takes the maximum state, treats `EMCMOT_ORIENT_NONE` and `EMCMOT_ORIENT_COMPLETE` as Task **DONE**, marks `IN_PROGRESS` beyond the deadline **ERROR**, and marks `FAULTED` **ERROR**. This is **ordinary command-completion/error handling**; it neither proves standstill nor commands/validates independent mechanical isolation. A cancel-to-NONE path can therefore satisfy the state test without proving an oriented physical spindle. The multi-spindle aggregation and cancellation interaction are **source-visible**, but exact timing/observable behavior requires a separately justified test; none was run. No claim of a proven machine-level failure or protective-stop defect.
