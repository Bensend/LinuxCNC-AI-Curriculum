# 4000-LC-NURBS-110 — non-XY biarc fallback and ignored approximation failure
**2026-11-01 | canonical motion generation / GUI preview | NON-GRADUATED | SOURCE-CONFIRMED conditional, TEST-CONFIRMED none.**

## Scope and version provenance
This is a separate downstream motion-generation problem from [NURBS-109](4400_LINUXCNC_NURBS_109_G52_DEFAULT_WEIGHT_P_SENTINEL_SOURCE_DOC_AUDIT_2026-11-01.md) and [SPLINE-69](4400_LINUXCNC_SPLINE_69_G93_F_PRESENT_BUT_NOT_APPLIED_G5_SOURCE_AUDIT_2026-10-31.md). Stable LinuxCNC **v2.9.10** uses a two-dimensional G5.2 converter and canonical `NURBS_FEED` ([stable converter](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/rs274ngc/interp_convert.cc#L140), [stable canonical biarc](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emccanon.cc#L1325)). Development **24e84c4506b41634240f7087f0295e361a954886** adds explicit G17/G18/G19 mapping in [`convert_nurbs`](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/rs274ngc/interp_convert.cc#L170) and sends `NURBS_G5_FEED(..., settings->plane)` at G5.3 ([source](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/rs274ngc/interp_convert.cc#L356)).

## Plane propagation — working normal path versus conditional failure
- Development maps **G17 XY** as `(NURBS_X,NURBS_Y)=(X,Y)`, **G19 YZ** as `(Y,Z)`, and **G18 XZ** as `(Z,X)`. The stored coordinate ordering follows the selected canonical plane; the XY and XZ/YZ mappings are distinct. This source trace establishes the intended plane-coordinate mapping at the interpreter boundary, not physical motion.
- Development [canonical `NURBS_G5_FEED`](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/task/emccanon.cc#L1558) ignores its formal `plane` parameter but calls `biarc`; the ordinary [`arc` helper](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/task/emccanon.cc#L1482) uses `canon.activePlane` to issue appropriately oriented `ARC_FEED`, so **ignoring the parameter alone is not evidence of wrong arcs**.
- However, [`biarc` fallback](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/task/emccanon.cc#L1538) on its near-degenerate/very-large-beta branch calls `STRAIGHT_FEED(lineno, p4x, p4y, p.z, ...)` **without checking the active plane**. That maps the two NURBS plane coordinates onto **machine X and Y** even for active YZ or XZ. Compare the [plane-aware `arc` helper](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/task/emccanon.cc#L1482) and [plane-aware Python preview `nurbs_feed`](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/rs274ngc/gcodemodule.cc#L429).
- Therefore **IF** a non-XY NURBS segment enters this fallback, its linear command uses the wrong coordinate slots. The condition's reachability for an ordinary machine program and the resulting Task/TP path are **NOT TESTED**; do not claim a reproduced axis excursion.

## Independent conditional failure — return value ignored
The stable [`biarc` implementation](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emccanon.cc#L1325) and development [`biarc`](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/task/emccanon.cc#L1506) can return 0 when the quadratic discriminant is negative or both candidate beta roots are positive, **before emitting arc/line commands**. Both versions' canonical NURBS loop calls `biarc(...)` **without checking its return value** ([stable NURBS_FEED](https://github.com/LinuxCNC/linuxcnc/blob/v2.9.10/src/emc/task/emccanon.cc#L1366), [development NURBS_G5_FEED](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/task/emccanon.cc#L1558)), then advances its local P0/P0T to the next sampled curve point. Thus a rejected approximation segment has no explicit error propagation and can be skipped in canonical emission. Whether a particular shape produces this condition or causes a visible path gap remains **UNKNOWN**.

## Why preview cannot be the only oracle
Development's [Python `gcodemodule::NURBS_G5_FEED`](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/rs274ngc/gcodemodule.cc#L441) samples `control_points.size()*15` **linear** preview points and maps coordinates by the requested plane; [Task canonical NURBS](https://github.com/LinuxCNC/linuxcnc/blob/24e84c4506b41634240f7087f0295e361a954886/src/emc/task/emccanon.cc#L1567) samples `control_points.size()*4` intervals and attempts **biarcs**. These are different geometric approximations and failure paths. A visually smooth preview is not proof that the Task canonical queue contains equivalent arcs/lines.
