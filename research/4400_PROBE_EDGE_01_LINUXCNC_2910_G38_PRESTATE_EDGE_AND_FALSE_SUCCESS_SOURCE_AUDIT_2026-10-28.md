# 4400-PROBE-EDGE-01 — LinuxCNC G38 probe prestate, rising-edge abort and false contact acknowledgment
**2026-10-28 | NON-GRADUATED source-level safety boundary; paper-only.** Session start 2026-10-28T19:32:03.912Z. This is a cross-machine LinuxCNC study, **not** evidence of a selected OpenPressBrake probe or an installed safety function.

## Question and novelty
Could a normal touch-probe indication be misread as a newly witnessed contact or protective stop when a sensor is already asserted, stuck, inverted, or changing during a different move? The [canonical safety index](../safety-course/SAFETY_COURSE_INDEX.md), [research plan](../SAFETY_COURSE_RESEARCH.md), historical [progress](../PROGRESS.md), and cumulative [design package](../safety-course/SAFETY_DESIGN_PACKAGE_TRACEABILITY_TEMPLATE.md) contain M66 ordinary input waits, M62/M63 queued outputs, jog/limit override and M19 acknowledgment studies but no G38 / `motion.probe-input` trace. **New causal mechanism:** the two *no-error* probe variants omit an initial target-state check, while the non-probe protective-looking reaction is rising-edge dependent. This does not create a new personnel-safety competency or reopen closed 1000–3000 courses.

## Four G38 variants — source-grounded state matrix
| G-code | Target input | `probe_type` | Already at target when command is accepted | End reached without target |
|---|---|---:|---|---|
| G38.2 | HIGH / contact | 0 | **Reject** with normal motion error | Normal motion error |
| G38.3 | HIGH / contact | 1 | **Prestate check skipped**; next probing processing can acknowledge existing HIGH as `probeTripped=1` without a new contact edge | No no-contact motion error; `probeTripped=0` |
| G38.4 | LOW / contact lost | 2 | **Reject** with normal motion error | Normal motion error |
| G38.5 | LOW / contact lost | 3 | **Prestate check skipped**; next probing processing can acknowledge existing LOW as `probeTripped=1` without a new break-contact edge | No no-contact motion error; `probeTripped=0` |

**Precise scope:** the two no-error variants are not guaranteed to move before `#5070` can become 1; source shows the existing level can satisfy the normal probe-completion condition. This is a static code-path conclusion, **not** a witnessed runtime or a claim about physical contact. `#5070=1` means ordinary software status `probe_tripped`, not an independently verified new sensor edge or machine safe state.

## Documentation/source discrepancy — preserve, do not smooth over
The tagged official G38 page says it is an error when *the probe is already in the target state*, without distinguishing G38.2/4 from G38.3/5. The tagged Motion implementation explicitly wraps this prestate check in `!(probe_type & 1)`, excluding G38.3 and G38.5. **DOC-CONFIRMED general wording versus SOURCE-CONFIRMED narrower behavior**. The code governs the inspected implementation. The intended documentation scope or bug classification is **UNKNOWN**; do not call it a reproduced LinuxCNC bug or silently generalize the documentation to all four modes.

## Non-probe movement is not a safety stop
`control.c` L716–778 reacts to a **LOW→HIGH** sampled transition outside a probe. For a coordinated move with queued motion, it may invoke ordinary `tpAbort` and motion error; for jog/homing it uses separate paths, subject to the documented `NO_PROBE_JOG_ERROR` and `NO_PROBE_HOME_ERROR` settings. If the input stays HIGH across motion episodes, there is **no new rising edge** for this particular branch. It is not a continuously checked, redundant, independent, safety-rated guard function. Nor does `tpAbort` prove instant stop, electrical isolation, physical restraint or the absence of stored energy.

## Architecture and human factors
- **Normal control:** G38.n, `motion.probe-input`, `#5070`, planner `tpAbort`, status and operator display. Useful for tool/part probing, process fault reporting and non-safety machine protection.
- **Diagnostics:** check sensor state before an ordinary probing sequence, check `#5070` after it, identify sensor and wiring, use an operator-readable fault and accessible recovery path. Avoid a green **PROBE OK / SAFE** conflation.
- **Independent safety:** risk/SRS-derived guarding, E-stop, interlock, safe motion/stop, reset and access functions implemented in an appropriate independent safety architecture, not inferred from probe wiring or ordinary FPGA/LinuxCNC.
- **Physical mechanisms:** actual stop/holding, gravity-load restraint, energy isolation and safe access require selected-machine validation. For a press brake, tool touch-off is not Y1/Y2 hydraulic stop/hold; for a mill/lathe, a tool setter is not spindle/axis safe standstill; for a robot/cell, a part-present probe is not personnel-presence sensing.
- Make legitimate tool-setter inspection and repair quick, guarded and comprehensible. If nuisance probe faults tempt an operator to bridge the input or disable an interlock, improve the service/diagnostic design; do not normalize bypass.
- If the basic independent personnel-protection proposition is unproved, **no personnel-exposed hazardous operation**. Any independently approved experimental work must remain isolated/remote with people outside the hazard zone and residual risk explicitly recorded.
