# 4400-PULSE-01 — Safety input test-pulse identity, cross-shorts and replacement wiring: original manufacturer audit
**Source review 2026-10-25; documentary evidence only; no selected-machine qualification.**

## Question and falsifiable prediction
Can two apparently independent normally closed protective-device channels remain **electrically indistinguishable** to a safety input receiver when both use the same pulsed test source? **Pre-source prediction (engineering hypothesis):** when both wires receive the same test waveform, a bridge between them may not create a timing disagreement; a controller can see two plausible ON channels despite the bridge. This is an **INFERENCE** pending exact receiver manual. Do not infer that every safety module has this defect.

## Original manufacturer evidence directly inspected
1. **Rockwell Automation, PointMax Digital I/O Modules, 5034-IB8S/5034-IB8SXT, "Wiring Diagrams for Safety Mode and Safety Pulse Mode," online documentation**, inspected 2026-10-25: https://www.rockwellautomation.com/en-pr/docs/technical/i-o/current/5034-pointmax/_online/5034-um002-ditamap/5034-ib8s-ib8sxt-details/safety-application-suitability-levels-input/5034-ib8s-ib8sxt-wiring-diagrams.html . Explicitly states that a short between two safety inputs **from the same test-output point is not detectable** in Safety Pulse Mode and instructs separate TO points. Its two-single-channel Cat.4/PL e illustrative rows show **n ≠ n\*** and **m ≠ m\***; its other high-level single-channel examples require a qualified sensor and/or external-wiring fault exclusion. The table is a conditional application suitability example, **not** a blanket claim that wiring two channels guarantees PL e.
2. **Pilz, PNOZmulti Installation Manual 1002265-EN-02, §5.6, printed pp. 25–26**, original PDF directly opened: https://www.pilz.com/download/open/PNOZmulti_Inst_Manual_1002265-EN-02.pdf . Explains that short/open-circuit controls depend on the hazard and sensor/actuator application; configurable input tests include test pulses for contact shorts and output feedback. It does **not** assert that every wiring topology detects every fault.
3. **Pilz, PNOZ m0p (ETH) Operating Manual 1002053-EN-08, §6.1, printed p. 17**, original PDF directly opened: https://www.pilz.com/download/open/PNOZ_m0p_Operating_Manual_1002053-EN-08.pdf . Explicitly reserves its test pulse outputs for testing inputs, **not driving loads**; forbids routing test pulse lines with actuator cables in an unprotected multicore cable; forbids reusing safety-mat test pulses for other purposes. Same original manual, §3.1, states standard inputs/outputs are not for safety-related applications. This manual is for the **PNOZ m0p**, not all Pilz devices.
4. **Rockwell Automation, POINT Guard I/O 1734-UM013R-EN-P, February 2024, p. 21**, original PDF indexed but direct open failed due to 11 MB retrieval limit: https://literature.rockwellautomation.com/idc/groups/literature/documents/um/1734-um013_-en-p.pdf . Search-extracted text describes test pulses to detect certain shorts and opens; numerical pulse timing is **INDEXED-ONLY, not page-visually verified** and is deliberately **not** used as a wiring or filter-design parameter here.

## Failure-path trace and counterexample
Normal protective device: two separate NC contacts -> field cables -> safety-rated receiver's SI0/SI1 -> safety logic -> qualified outputs -> monitored final elements -> physical stop/hold. **Fault:** an insulation bridge shorts SI0 and SI1; if both derive from the **same** TO waveform, the receiver's time-domain test cannot distinguish the two sources under the documented Rockwell mode. Channel duplication is not diagnostic diversity. A shared supply, incorrect pulse-mode setting, copied configuration, replacement module, crushed multicore cable, or bridged test-output terminal can erase an assumed fault detector. These causal extensions are **INFERENCE**, not claims of observed failures.

**Second hazard:** a field technician sees a test-output terminal marked 24 V and uses it to drive a lamp or relay. For the inspected Pilz model that violates explicit OEM use; it may compromise diagnostic assumptions and creates a maintenance substitution trap. This is not an instruction to fault-inject a live safety circuit.

## Architecture and acceptance implications
- Preserve physical separation of **normal LinuxCNC/HAL/FPGA status**, **safety input wiring and logic**, **monitored final elements**, and **hydraulic/gravity energy restraint**.
- For each safety function, trace *actual* sensor type and contacts, SI/TO assignments, receiver model/firmware/mode, field-cable routing, short/open detection claims, configuration checksum/version, output/EDM path and physical hazard outcome.
- Require an independent safety engineer to reconcile sensor interface type (dry contact, OSSD, monitored electronic output), test pulses, external power, fault exclusions, common cause and safety-function calculation. Do not casually connect a sensor's active OSSD output to a contact test-pulse source.
- **Human factors:** print SI/TO pairing and exact device model inside cabinet, use keyed terminal identifiers, maintain an as-built terminal map, avoid hidden splices, provide visible nonhazardous diagnostics, and make correct replacement/retest faster than bypassing the safety circuit.
- **Physical G0/G1 HOLD:** no personnel-exposed hazardous operation until qualified as-built input/logic/final-element/stop/hold/guard/LOTO/rearm evidence. A bench-only continuity or PLC indicator is not physical validation.

## Cross-vendor source correction — terminal label does not define output function
**DOC-CONFIRMED, direct official Rockwell product documentation:** the 5034-IB8S/XT technical page explicitly says **all test outputs support muting-lamp outputs** (https://www.rockwellautomation.com/en-us/docs/technical/i-o/current/5034-pointmax/_online/pointmax-i-o-modules-details-ditamap/digital---safety-i-o-modules/5034-ib8s-ib8sxt-details/5034-ib8s-safety-digital-8-input-module.html). The indexed original 5034-UM002D-EN-P also lists configurable Not Used, Standard Output, Pulse Test, Power Supply and Muting Lamp functions, but **direct PDF opening failed due to ~30 MB size**; treat the full mode list as **INDEXED-ONLY** until independently opened. This **does not conflict** with Pilz PNOZ m0p's model-specific prohibition on using *its* test outputs to drive loads. Therefore never generalize "every TO is only for input tests" or "every TO can drive a lamp": **exact model + configured mode + intended load** govern. Muting-lamp support is not proof of a qualified safety final-element output.
